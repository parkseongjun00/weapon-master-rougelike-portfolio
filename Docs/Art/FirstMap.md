## 1. 장소의 정체성

- 첫 맵은 현대적인 한국의 먹자골목·상가 거리다.
- 한국 상가 거리는 다양한 장소로 확장할 게임의 첫 스테이지다. 게임 전체의 장소를 한국 상가 거리로 한정하지 않는다.
- 현실적으로 있을 법한 가상의 한국 상권으로 구성한다.
- 방이맛골은 거리와 상가의 관계를 이해하는 참고 대상이다. 실제 장소의 측량 재현이나 특정 건물·상호의 복제를 목표로 하지 않는다.
- 친숙하고 일반적인 상권을 첫 맵의 출발점으로 삼는다.
- 실제 리소스의 현실성은 건물 외곽선, 층별 연결, 점포 구획, 출입구와 외벽의 관계로 판단한다. 사진처럼 보이는 재질이나 실존 장소와의 일치는 요구하지 않는다.
- 최종 아트 스타일, 조명, 시간대, 색 팔레트와 세계관 사건은 별도로 확정한다.
- 게임 공통의 현장 무기 확보·교체 콘셉트는 GDD 1장을 기준으로 한다. 적 정체성·표현의 검토 상태는 [적 디자인 문서](EnemyDesign.md)를 함께 읽는다.

## 2. 공간 구성과 규모

### 2.1 확정된 구성 원칙

- 전체 외곽은 160×160m인 제한형 맵이다.
- 넓은 주 거리와 교차로가 주요 전투 공간이다.
- 짧은 지선과 코너의 열린 공간은 보조 공간이다.
- 격자형 가로·세로 길을 허용한다. 교차로의 바닥과 통행 영역은 하나의 자연스러운 공간으로 이어진다.
- 건물 내부, 블록 안쪽 필지와 건물 사이 틈은 현재 플레이 공간이 아니다. 후면 작업 공간이라는 설정은 통행 허용을 뜻하지 않는다.
- 공사 구역과 새로운 상호작용 요소는 이번 환경 리소스 제작 범위에서 제외한다. 기존 무기 상호작용 등 게임 규칙은 유지한다.

---

### 2.2 현재 배치안의 수치

| 항목 | 현재 배치안 | 취급 |
|---|---|---|
| 동서 주 거리 | 18m | 보행 여유부를 포함한 전체 거리 폭 |
| 남북 교차 상업로 | 16m | 보행 여유부를 포함한 전체 거리 폭 |
| 남동 짧은 지선 | 14m | 보행 여유부를 포함한 전체 거리 폭 |
| 건물·1층 점포 | 건물 24개, 점포 23개 | 배치도·좌표 스냅샷의 현재 구성. 영구적인 콘텐츠 수량 목표가 아님 |

- 세 거리 폭은 배치 검증 중인 수치다. 차도 폭만을 뜻하지 않는다.
- 코너 전면 공지는 건물을 교차로 모서리에서 물려 확보한 열린 앞마당이다. 별도 실내나 상호작용 시설이 아니다.
- 하역 포켓과 정류장 여유부는 공간 용도를 구분한 영역이다. 적재물·정류장 소품의 배치나 기능을 확정한 것은 아니다.

---

### 2.3 플레이 스케일 참고값

| 항목 | 참고값 | 확인 방법 |
|---|---|---|
| 캐릭터 높이 | 약 2m | 현재 플레이어 모델과 씬에서 확인 |
| 기본 이동 속도 | 6m/s | `PlayerMovement`의 기본값과 씬 설정, 런타임 배율을 구분 |
| 카메라 지면 표시 범위 | 약 32×17m | 실제 카메라 설정, 화면 비율과 측정 위치에서 재확인 |

- 참고값을 맞추기 위해 카메라나 플레이어를 자동 변경하지 않는다.
- 배치도의 카메라 사각형과 이동 반경은 공간 비교 도구다. 런타임 화면이나 장애물을 고려한 실제 이동 경로를 보장하지 않는다.

## 3. 블록별 성격

| 블록 | 방향 | 층수 중심 | 표현 방향 |
|---|---|---|---|
| 북서(NW) | 오래된 식당가 | 2~4층 | 오래된 음식점 건물군과 축적된 상가 외관 |
| 북동(NE) | 비교적 정돈된 상가 | 3~5층 | 상대적으로 정돈된 건물과 점포 전면 |
| 남서(SW) | 낮은 상가와 작업·후면 공간 | 2~4층 | 저층 상점과 업무·창고·작업 용도의 후면 |
| 남동(SE) | 야간 상권과 숙박업 | 4~6층 | 음식점·주점과 상층의 노래방·숙박 용도 |

- 같은 동네 안에서 건물 연식, 높이, 외관과 용도가 달라지는 정도로 구분한다.
- 블록마다 별개의 세계나 전혀 다른 아트 스타일을 적용하지 않는다.
- 남동의 야간 상권은 업종 성격이다. 맵 전체의 시간대를 밤으로 확정한 것은 아니다.
- 현재 그레이박스의 블록별 색상은 구분용이다. 최종 재질과 팔레트의 기준이 아니다.

## 4. 건물과 점포의 관계

- 건물 단위의 외곽선과 소속 점포를 먼저 읽을 수 있게 구성한다.
- 1층과 상층은 같은 건물 몸체로 자연스럽게 이어진다. 여러 건물을 받치는 공통 1층 덩어리 위에 상층을 임의로 쌓는 구성을 기본으로 삼지 않는다.
- 점포는 소속 건물의 1층 전면 안에서 구획한다. 이웃한 두 건물에 걸쳐 하나의 점포가 놓이지 않게 한다.
- 현재 국밥집은 `SW02`, 포차는 `SW03`에 각각 속한다. 이름은 업종을 설명하는 표기이며 실존 상호가 아니다.
- 블록 안쪽은 개별 건물의 몸체와 닫힌 후면 필지로 읽히게 한다. 구룡채성처럼 연결된 거대 고밀도 구조물을 목표로 하지 않는다.
- 도로와 열린 공간에 노출되는 측면·후면도 실제 건물처럼 구성한다. 현재 그레이박스에서 창문이 전면에 집중된 상태는 실제 리소스 제작 시 검토할 항목이다.
- 모든 면에 같은 창문을 반복할 필요는 없다. 인접 건물과 맞닿는 벽, 계단실과 후면 용도 등 건물 관계에 맞춰 판단한다.

## 5. 배치도와 그레이박스의 관계

| 자료 | 역할 |
|---|---|
| [배치도 HTML](../../Design/Arena/arena-food-street-concept.html) | 건물별 위치·크기·층수·점포 소속과 통행 영역을 확인하는 독립 HTML |
| `Assets/Scenes/GameScene.unity` | 실제 씬의 배치·충돌·카메라와 플레이 상태 확인 |

- 현재 씬에는 `BangiGraybox_160m`와 이름에 `_Previous_`가 붙은 이전 구성들이 남아 있다. 후속 작업 전에 활성 상태와 검사 대상을 확인한다.
- 배치도 좌표는 북서 모서리 기준이다. 현재 씬의 배치는 Unity 지면 좌표를 `X = x - 80`, `Z = 80 - y`로 변환한다.
- 그레이박스는 공간 규모와 건물·거리 관계를 검증하는 도구다. 실제 리소스의 창문·간판·외벽 디테일 완성도를 판정하는 최종 시안이 아니다.
- 사용자의 씬 관찰과 피드백을 전체 전투·스폰·이동 검증 완료로 확대 해석하지 않는다. 최종 배치 합격 판정은 아직 기록되어 있지 않다.

## 6. 카메라 정책과 후속 과제

- 인게임 카메라는 월드 기준 쿼터뷰 배치를 사용하며 주시 높이를 평상시 Player 기준0에서 근접 시1.5까지 선형 보간한다. 추적·회피 기준점은 높이1.5로 고정한다. 구현은 개발 노트3.29, 사용자 직접 확인 통과는3.30을 따른다.
- 카메라는 WorldObstacle이 상체 기준점을 가리면 캐릭터 쪽으로 당겨 기준점까지의 시야 확보를 시도한다.
- 전신과 주변 전투 공간의 상시 노출을 보장하지 않으며 확대 정도와 실제 전투 가독성은 별도 수용 대상으로 둔다.
- 카메라 자체가 건물 내부로 들어가는 현상은 해결 대상이다. 현재 충돌·시야 보정의 구현 기록은 [개발 노트3.27](../DevNotes/03-PlayerAnimation.md#327-deoccluder로-낮은-건물의-시야-가림-대응), 남은 수용·빌드 검증은 [Backlog 14](../Backlog.md#14-고정-시점-카메라의-건물-내부-진입-방지)를 따른다.
- 건물 불투명도 조절은 선택 사항이다. 적용 여부와 구현은 [Backlog 15](../Backlog.md#15-건물-시야-가림-허용-및-불투명도-조절-검토)에서 검토한다.
- 환경 리소스 제작만을 이유로 건물 높이를 일괄 축소하거나 카메라·투명화 시스템을 함께 구현하지 않는다.

## 7. 제작 착수 시 확인할 사항

### 7.1 사용자 확인 제작 방향

- 건물은 현재 배치와 그레이박스의 치수를 출발점으로 Unity의 단순한 도형을 조립하거나 같은 형태의 메시를 생성해 제작한다.
- 건물 몸체와 점포 외관을 기반으로 외벽 재질, 창틀, 유리, 차양, 간판을 교체·조정하는 제작 흐름을 사용한다.
- 간판은 판의 앞면 이미지와 색을 교체하는 방향으로 제작한다. 글자·상호·그래픽의 구체적인 디자인은 별도로 검토한다.
- 작은 설비와 소품은 필요에 따라 별도 제작·생성하고 건물과 결합한 결과를 확인한다.
- 대표 시제품은 `NW03` 한 채다. 다른 건물로의 확대 적용은 대표 시제품 검토 뒤 별도 요청 범위에서 진행한다.
- 사용자가 요청한 외관 방향은 관리된 상가와 개성 있는 점포가 모인 거리다. 연식 있는 건물과 새로 정비한 점포 전면을 함께 표현한다.
- `NW03`의 유리는 `#91A6AD`를 지정색으로 사용하고 반사·그라데이션·내부 투시 없이 단색으로 표현한다. 첫 맵 전체의 유리 재질 기준으로 확대하지 않는다.

---

### 7.2 현재 시제품과 검증 상태

- `GameScene.unity`의 활성 `BangiGraybox_160m` 아래 `Building_NW03/NW03_ArtPrototype`에 외관 시제품과 독립 재질이 적용되어 있다.
- 구현·에셋 경로와 검증 결과는 [환경 아트 개발 노트](../DevNotes/04-EnvironmentArt.md)를 기준으로 한다.
- 기존 NW03 부품은 남겨두고 렌더러를 숨겼다. 기존 배치·충돌과 다른 건물·저장된 카메라는 유지했다.
- 앞면은 두 점포, 뒷면은 작은 창문·관리용 문·설비로 구분한다. 창문 깊이와 점포 마감은 현재 초벌 표현이다.
- 재질 조절 기반은 구현되었으나 사용자 피드백 기준으로 현실성과 비주얼 완성도 개선이 필요하다.
- 최종 아트 스타일·배치 합격·전체 맵 반복 제작·실행 빌드 성능 검증은 완료 상태로 취급하지 않는다.

---

### 7.3 다음 실행의 경계와 미확정 항목

- 실제 리소스 생성·가져오기·씬 배치는 해당 작업을 요청받은 범위에서 진행한다. 문서 기록 자체는 후속 실행 승인이 아니다.
- 후속 세션은 기준 문서와 배치도, 실제 씬의 관계를 확인하고 차이와 미확정 항목을 먼저 보고한다.
- 미확정: 재사용할 건물·부품의 종류와 수량, 최종 색 팔레트·조명·시간대, 간판 디자인, 소품 구성, 재질·텍스처·폴리곤 예산.
- 현실성 개선 후보와 열린 검증 과제는 [Backlog 16](../Backlog.md#16-nw03-현실성-개선과-환경-리소스-검증)에 둔다.
- 예전 Meshy 구독 종료일을 현재 작업의 전제조건으로 사용하지 않는다. 도구 사용 조건은 실제 생성 요청에 필요한 범위에서 확인한다.
- 배치 검증과 실제 인게임 시점의 외관 검증을 구분한다. 구체적인 합격 수치와 시험 시간은 미확정이다.
