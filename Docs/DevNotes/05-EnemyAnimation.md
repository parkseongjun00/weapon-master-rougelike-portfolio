### 5.2 전투 처리와 표현의 연결

> 후속 변경(2026-10-19): [일부 변경] 접촉 피해를 유지한 당시 구현·검증은 보존한다. 유형별 공격 피해 정책은 [5.29](#529-유형별-공격-피해-정책으로-전환)에서 확정했으며 기본 적의 코드 전환은 [5.33](#533-공통-무기모션과-기본-적-펀치) 에서 적용했다. 기존 공격 연결·이동·풀·보상 기록 전체의 폐기를 뜻하지 않는다.

> 후속 변경(2026-10-15): [일부 변경] 접촉 피해 이벤트와 공격 재생 연결은 이후 제거했다. 현재 동작은 [§5.7](#57-공격-재생-연결-보류)을 따른다. 사망·풀 반납·재스폰 설명은 이 변경의 폐기 대상이 아니다.

- **접촉 공격**: EnemyContactDamage가 기존 피해를 적용한 뒤 DamageApplied 이벤트를 발행한다.
	- EnemyAnimationController가 이벤트를 구독하여 선택 공격 클립을 재생한다.
	- 피해량 8·쿨다운 1초·PlayerBody 제한을 유지했다.
	- 타격 프레임과 피해 시점의 동기화는 이번 구현에 포함하지 않았다.
- **사망 확정**: HP가 0이 되면 추격·콜라이더·접촉 피해·간격 계산·체력바를 즉시 종료한다.
	- XP는 기존 EnemyXPReward가 사망 이벤트로 지급한다.
	- 처치 알림은 EnemySpawner.NotifyEnemyKilled에서 즉시 발행한다.
- **풀 반납**: EnemySpawner.ReturnEnemy는 객체 반납만 담당한다.
	- 퇴장 클립이 비어 있으면 즉시 반납한다.
	- 퇴장 클립이 있으면 전투 기능을 종료한 외형만 재생하고 반납한다.
	- 재생이 중단되면 대기를 끝내며, 정상 재생도 클립 길이를 대기 상한으로 삼는다.
	- 일시정지는 게임 시간과 함께 재생·반납 대기를 멈춘다.
- **재스폰**: 체력 초기화 뒤 EnemyAI.ResetForReuse를 같은 프레임에 호출한다.
	- 콜라이더·접촉 피해·쿨다운·체력바·기본 자세·사망 및 반납 상태를 복원한다.
	- 비활성화 시 이벤트 구독과 남은 코루틴을 정리한다.

### 5.4 이후 클립 적용 절차

> 후속 변경(2026-10-19): [일부 변경] 접촉 피해를 유지한 당시 구현·검증은 보존한다. 유형별 공격 피해 정책은 [5.29](#529-유형별-공격-피해-정책으로-전환)에서 확정했으며 기본 적의 코드 전환은 [5.33](#533-공통-무기모션과-기본-적-펀치) 에서 적용했다. 기존 공격 연결·이동·풀·보상 기록 전체의 폐기를 뜻하지 않는다.

> 후속 변경(2026-10-15): [일부 변경] 공격 슬롯만 연결해도 공격 동작이 재생된다는 절차는 현재 적용할 수 없다. 공격 규칙 확정과 재생 연결이 먼저 필요하다([§5.7](#57-공격-재생-연결-보류)). 퇴장 클립 연결은 이 변경의 폐기 대상이 아니다.

1. 준비한 FBX를 Humanoid로 가져오고 Avatar 유효성과 변형을 확인한다.
2. 공격·퇴장 클립은 반복 재생을 끄고 제자리 동작을 기준으로 확인한다.
3. Enemy_Grunt_01 프리팹 루트의 EnemyAnimationController에서 Attack Clip·Exit Clip을 연결한다.
4. Play Mode에서 실제 모델의 타격 동작·퇴장 길이·보상을 확인한다.
5. 주먹이 닿는 시점으로 피해 판정을 바꾸려면 별도의 전투 규칙 변경으로 검토한다.

- **상태 그래프**: 전용 EnemyGrunt 컨트롤러의 Idle·Move·Attack·Exit를 유지한다.
	- 런타임 Override Controller가 두 선택 슬롯을 교체한다.
	- Inspector 슬롯 연결만으로 재생 경로까지 연결된다.
- **현재 슬롯**: 실제 사용자 클립은 미제공이며 두 선택 슬롯을 비워 두었다.
	- 검증용 임시 클립을 프리팹에 저장하지 않았다.

### 5.5 검증 결과와 한계

> 후속 변경(2026-10-19): [일부 변경] 접촉 피해를 유지한 당시 구현·검증은 보존한다. 유형별 공격 피해 정책은 [5.29](#529-유형별-공격-피해-정책으로-전환)에서 확정했으며 기본 적의 코드 전환은 [5.33](#533-공통-무기모션과-기본-적-펀치) 에서 적용했다. 기존 공격 연결·이동·풀·보상 기록 전체의 폐기를 뜻하지 않는다.

> 후속 변경(2026-10-15): [일부 변경] 아래 공격 재생 검증은 연결 제거 전 구현에 대한 결과다. 제거 후 기록은 [§5.7](#57-공격-재생-연결-보류)을 따르며, 해당 수정 뒤 Play Mode 재검증은 실행하지 않았다.

- **컴파일**: 변경한 코드의 별도 컴파일과 Unity에서의 코드 로드·제작 스크립트 실행이 성공했다.
- **Play Mode 생애주기**: 저장 기능이 없는 별도 씬에서 22개 검증을 통과했다.
	- 실제 추격·Move 전환, 물리 접촉 피해 8, 쿨다운, PlayerAttack 접촉 제외를 확인했다.
	- 빈 슬롯의 즉시 반납과 임시 클립의 공격·퇴장 연결을 확인했다.
	- 사망 즉시 보상·처치 집계, 전투 제외, 일시정지, 중복 보상 방지를 확인했다.
	- 같은 객체의 반복 재사용과 다섯 생애의 처치 수 5·XP 50을 확인했다.
- **게임 시점**: GameScene 사본의 실제 Play Mode에서 새 적 다섯 명과 체력바를 확인했다.
	- 저장 관련 추적기를 사본에서만 끄고 배치·카메라·조명은 원본 구성을 사용했다.
	- 체력바의 월드 회전 약 (53, 0, 0)을 확인했다.
	- 검증 후 원래 GameScene으로 돌아가고 임시 에셋 씬을 제거했다.
- **검증 도구 보정**: 첫 검증은 백그라운드 실행 정지와 초기 Animator 전환 대기 때문에 실패했다.
	- 검증 중 Application.runInBackground만 임시로 켰다.
	- 실제 물리·Animator 갱신을 기다린 뒤 검증하고 원래 실행 값을 복원했다.
- **남은 검증**: 실제 사용자 공격·퇴장 클립, 직접 조작한 근접·원거리 전투 회귀, 실행 빌드·성능, 최종 아트 수용은 미검증이다.
- **기존 씬 메모**: 플레이어 근처에 별도로 놓인 동일 FBX의 정적 T포즈 모델은 기존 배치로 보존했다.
	- 이 모델은 스포너로 생성한 새 적이 아니다.
	- 해당 배치 정리 여부는 후속 판단 사항이다.

### 5.6 대표 적 프리팹 통일

> 일자: 2026-10-14
> 상태: 사용자 삭제 승인 후 완료.

Enemy_Basic과 Enemy_Grunt_01의 혼동을 줄이기 위해 활성 적 프리팹을 Enemy_Grunt_01로 통일했다.

- **기존 프리팹 삭제**: Unity AssetDatabase로 Enemy_Basic 프리팹과 메타 파일을 함께 삭제했다.
	- 5.1의 원본 보존은 교체 당시의 기록이며, 이후 사용자 요청으로 삭제했다.
- **씬 제작 도구**: Stage1SceneBuilder는 대표 적 프리팹을 불러와 사용한다.
	- 프리팹을 찾지 못하면 기존 씬을 정리하기 전에 중단한다.
- **검증**: Unity 코드 로드와 기존 프리팹 삭제가 성공했다.
	- 저장된 씬·프리팹·데이터 에셋과 열린 씬의 스포너에 이전 프리팹 참조가 없었다.
	- 씬 제작 도구의 적 선택 메서드가 Enemy_Grunt_01을 반환했다.
	- 삭제 전후 GameScene과 새 프리팹의 파일 해시가 동일했다.
	- 이번 정리에서는 Play Mode와 전체 씬 재생성을 실행하지 않았다.

공격 패턴에 앞서 일반 이동을 NavMeshAgent로 전환했다. 기존 직접 이동은 목적지 방향의 장애물 앞에서 멈추며 우회 경로를 찾지 않았다. 슬롯·추종·이동 책임을 유지하고 우회·회피를 표준 내비게이션으로 처리하는 것이 목적이다. 성능 향상은 측정하지 않았다.

- **이름·경계**: TargetFollower를 SlotFollower, CharacterMovement를 NavigationMovement로 변경했다.
	- 두 스크립트는 AssetDatabase.MoveAsset으로 이동하고 기존 GUID·프리팹 연결을 보존했다.
	- EnemyAI → SlotFollower → NavigationMovement → NavMeshAgent, SlotFollower → SurroundSlots 방향을 유지한다.
	- NavigationMovement는 AI·슬롯·스포너·공격 종류를 참조하지 않는다.
	- EnemyAI는 생애주기 책임으로 NavigationMovement.ResetForReuse·Suspend를 직접 호출한다. 사망한 개체를 Agent 회피에서도 즉시 제외하기 위한 연결이며, 슬롯 판단은 추가하지 않았다.
	- EnemyAnimationController는 NavigationMovement.CurrentSpeed를 읽는다. 플레이어는 기존 PlayerMovement·CharacterController를 사용한다.
- **해당 기록의 코드**: [SlotFollower](../../Scripts/Movement/SlotFollower.cs), [NavigationMovement](../../Scripts/Movement/NavigationMovement.cs), [EnemyAI](../../Scripts/Enemies/EnemyAI.cs), [EnemySpawner](../../Scripts/Enemies/EnemySpawner.cs), EnemyAnimationController (공개본 생략: `../../Scripts/Enemies/EnemyAnimationController.cs`).
- **이동 계약**: SetDestination·Stop·Face·HasArrived·State·CurrentSpeed·IsReady를 제공한다.
	- State는 Inactive·PathPending·Moving·Unreachable·OffNavMesh를 구분한다. Moving은 경로가 유효하다는 상태이며 실제 속도0과 구분한다.
	- 목적지는0.2초 간격·수평0.1m 이상 변화 시 재요청한다. 새 예약은 이전 이동을 중단한 뒤 즉시 요청한다.
	- NavMesh 위치 검색 반경은0.15m이며 수평 보정은 최대0.05m로 제한한다. 큰 보정으로 여러 슬롯을 한 위치로 합치지 않는다.
	- 완전한 경로·남은 거리·실제 슬롯 거리로 도착을 판단한다. 부분 경로 끝을 도착으로 취급하지 않는다.
	- 경로 계산 중에는 막힘 시간을 누적하지 않는다. 유효 경로에서 실제 속도0.05m/s 미만이3초 지속되면 해당 Revision의 슬롯을 재시도한다. 슬롯 방향에서 멀어지는 정상 우회는 실패로 취급하지 않는다.
	- 슬롯 도착0.1m·재추적0.2m, Agent 정지 거리0.05m로 설정했다.
	- 기존 전체 개체 순회의 직접 분리와 Transform 이동은 제거했다. 일반 이동 위치는 Agent가 갱신하며 회전은 이동 컴포넌트가 실제 이동 방향·Face 명령으로 처리한다.
- **생애주기**: Agent는 프리팹에서 비활성이다. NavigationMovement.OnEnable은 준비 상태를 해제하고 이전 경로를 재개하지 않는다.

### 5.31 반경 계산 오차로 인한 슬롯 재구성 반복 수정

> 후속 확인(2026-10-19): 사용자가 이동·정지 반복 증상의 해결을 확인했다([5.32](#532-반복-정지-수정의-사용자-확인과-커밋)). 아래 검증 대기는 당시 상태로 보존한다.

> 일자: 2026-10-19
> 상태: 사용자 로그 재현으로 원인 확인 후 승인된 반경 비교3곳 수정. 수정 후 실제 이동·로그 재확인은 사용자 대기.

사용자는 플레이어가 멈춰 있으면 적이 접근하지만 움직이면 정지·재출발을 반복하며 거의 전진하지 못한다고 보고했다. 임시 NavTrace로 실행 순서를 확인하고 반경 비교만 수정했다.

- **원인 확인**: 같은705프레임에서 반경0.5 → 0.50000006의 변화로 layoutSeq133 재구성, 대표 적 Revision396 → 399 변경, ReservationChanged 정지를 확인했다.
	- 당시 대표 적의 목표 거리는 약86m이고 경로는 PathComplete였다.
	- 재구성이 멈춘 구간에는 layoutSeq204·Revision612를 유지하며 실제 속도3.5m/s로 이동했다.
	- 기존 strict 비교가 lossyScale의 미세한 수치 오차를 실제 몸체 크기 변화로 취급했다.
- **수정**: SurroundSlots의 대상 반경 변경과 최대 참여자 반경 증가, SlotFollower의 참여 반경 변경 판단에 Mathf.Approximately를 적용했다.
	- 최대 반경은 기존보다 크고 근사 비교에서도 다를 때만 늘린다.
	- 무시한 차이는 기준 반경에 덮어쓰지 않아 작은 실제 변화가 누적되면 기존 기준과 다시 비교한다.
	- 실제 크기 변화·예약 Revision 보호·정지 및 경로 동작은 유지한다.
- **범위**: 게임 코드 수정은 SurroundSlots.cs·SlotFollower.cs의 조건3개다.
	- NavigationMovement·씬·프리팹·플레이어·공격·이동 수치는 이번 수정에서 바꾸지 않았다.
	- Editor 전용 NavigationTrace와 정지 사유 계측은 사용자 재확인을 위해 유지했다.
- **근거 보존**: 재현 로그를 AgentScripts/NavigationMigration/RadiusTrace-before.log에 로컬 보존했다.
- **검증**: 수정 후 Unity recompile_status의 completed·failed=false·errors0과 Play paused 유지를 확인했다.
- **남은 확인**: 사용자가 새 Play에서 정지 → 이동을 재현한 뒤 일시정지한다.
	- 미세한 반경 차이로 LayoutRebuild·ReservationChanged 정지가 반복되는지와 실제 추종 회복을 확인한다.
	- 정상 스폰·안쪽 충원·실제 몸체 크기 변화에 따른 예약 변경과 노이즈 재구성을 구분한다.
	- Codex는 Play 재개·종료·자동 동작 검증을 수행하지 않았다.
