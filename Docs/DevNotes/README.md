# 개발 노트: 공통 규칙과 색인

> 공개 편집본 p3 · 2026-10-27 · 문서 원본 `37ba4c4`. 공개 범위와 코드 기준은 [문서 색인](../README.md)을 따른다.


주요 의사결정과 그 이유를 짧게 보존해 같은 조사·논쟁·실패를 반복하지 않도록 한다. 각 기록은 당시의 판단이며 현재 동작을 보장하는 명세가 아니다. 현재 코드와 다르면 후속 기록을 먼저 확인한다.

---

## 0. 일러두기

### 0.1 확정된 결정과 유의미한 결과를 기록한다

- 사용자 결정 또는 구현 과정에서 확정된 판단을 남긴다.
- 미채택 제안을 확정 결과로 쓰지 않는다.
- 문제·제약·기각 이유·실패 조건·판단의 한계를 보존한다.
- 단순 작업 보고·승인 경계·변경 파일 목록·초안 정리 보고는 반복하지 않는다.

---

### 0.2 모든 결정에 같은 네 목차를 같은 순서로 사용한다

| 고정 목차 | 작성할 내용 |
|---|---|
| 문제 | 판단이 필요했던 상황·제약 |
| 결정 | 선택·변경·기각한 내용 |
| 근거 | 선택 이유·대안과의 차이 |
| 검증과 한계 | 확인 방법·결과·미확인 범위·후속 변경 |

- 결정 제목은 기존 형식의 `### N.M`을 유지한다.
- '문제'·'결정'·'근거'·'검증과 한계'는 내용의 길이와 형식에 관계없이 상위 불릿으로 쓴다.
- 네 항목명은 `- **문제**`처럼 굵게 표시해 하위 본문과 구분한다.
- 설명과 요점 목록은 하위 불릿으로 쓰고, 표·코드 블록 등은 해당 항목 아래에 들여써 배치한다.
- 네 목차는 생략하지 않되 분량을 맞추거나 빈 내용을 만들지 않는다.
- 설계만 확정했다면 검증과 한계에 구현·실행 결과가 없음을 명시한다.
- 새 판단 없이 확인 결과만 있는 기록은 관련 결정의 검증과 한계에 날짜를 구분해 합친다.
- 틀에 맞지 않으면 독립적인 결정인지 먼저 확인하고, 보존할 판단이 있을 때 목차의 적합성을 검토한다.

---

### 0.3 표 → 불릿 → 문단 순으로 표현 방식을 검토한다

- 비교·대응 관계·여러 항목의 속성은 표를 우선한다.
- 독립적인 요점·조건은 불릿으로 쓴다.
- 연결된 인과관계는 짧은 문단으로 설명한다.
- 한 문장을 억지로 표로 만들거나 긴 설명·중첩 목록을 표 안에 넣지 않는다.
- 한 요점당 한 문장을 기본으로 하되 문장을 나누기 위해 중첩을 늘리지 않는다.

---

### 0.4 당시 판단은 보존하고 표현·중복은 정리할 수 있다

- 새 판단으로 기존 결정을 뒤집을 때는 후속 기록을 추가한다.
- 편집상 압축·중복 제거·관련 검증 통합은 결정의 의미·사유·확인 범위를 보존하는 조건으로 허용한다.
- 실패한 가설은 확인 결과와 구분하고 현재 사실처럼 고쳐 쓰지 않는다.
- 통합 전의 날짜와 결정 변화를 남기고 과거 검증을 새 구현의 검증으로 옮기지 않는다.
- 검사 개수보다 확인 대상을 우선하며 성능 수치는 측정 조건·실패한 측정·해석 한계와 함께 남긴다.

---

### 0.5 파일 분류와 기존 번호·참조를 유지한다

- 파일은 `NN-Topic.md` 형식이며 파일 번호와 `## N`을 맞춘다.
- 번호는 기록 식별자이며 개발 단계나 우선순위가 아니다.
- 통합으로 생긴 결번은 재사용·재번호하지 않고 새 항목은 기존 최대 번호 다음에 추가한다.
- 남는 항목의 제목·앵커를 유지하고, 통합한 항목은 원래 제목의 명시적 앵커를 통합 위치에 남긴다.

---

### 0.6 편집 전에 이 파일과 대상 기록을 함께 읽는다

- WritingGuide.md의 표기·간결한 근거·제목 번호·구분선을 기본 적용한다.
- 이 문서의 고정 목차·표현 선택 규칙은 기존의 불릿 분해 규칙을 대체한다.
- 역사적 판단의 차이는 보존하되 같은 내용을 다시 설명하기보다 기록 위치로 연결한다.
- 결정 기록은 항목별 날짜를 사용하고 파일 버전·별도 변경 이력은 두지 않는다.
- README 규칙 변경은 아래 편집일로 표시하며 결정 파일에 규칙 변경 보고를 추가하지 않는다.

---

### 0.7 결정 변경 시 영향을 받는 이전 기록에 최신 위치를 안내한다

- 해당 절의 제목 아래에 `> 후속 변경(안내 작성일): [일부 변경] 변경 범위와 최신 기록 링크.` 형식으로 적는다.
- 절 전체가 대체되면 [대체됨], 판단 전체가 폐기되면 [폐기됨]으로 구분한다.
- 일부 변경은 바뀐 부분만 명시하고 유효한 다른 결정·당시 검증까지 폐기하지 않는다.
- 이후에도 변경되면 관련 결정·코드 안내·적용 절차·검증의 연결을 최신 기록으로 갱신한다.
- 이번 정리에서는 중복된 후속 안내를 검증과 한계로 압축했으며 다음 의미 변경 때도 관련 안내를 확인한다.
