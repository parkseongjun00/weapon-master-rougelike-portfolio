## 4. 첫 맵 환경 리소스

### 4.1 건물 전체 생성에서 단순 형상 제작으로 전환

<a id="41-제작-방식-전환"></a>

> 일자: 2026-10-12

- **문제**

	- 건물 전체 생성 시험에서 불필요한 바닥·문자·창문이 포함되고 창틀·차양·벽면이 뭉개졌다.

- **결정**

	- 현재 그레이박스 배치에서 단순 기하로 건물 기본 구조를 제작했다.
	- 앞·뒤 참고 이미지를 구분하고 재질·간판 교체 중심의 반복 제작을 택했다.
	- 유리는 #91A6AD 단색으로 두고 반사·그라데이션·내부 투시는 제외했다.
	- NW03 한 채로 제작 방식을 먼저 시험했다.

- **근거**

	- 최초 생성에서 생긴 형태 손실과 리메시의 감량 손실을 구분했다. 기본 구조는 정확한 단순 형상으로 만들고 의미 있는 소재를 독립 조절하도록 했다.

- **검증과 한계**

	- NW03 시제품을 구현했다. 사용자 비교의 리메시는 삼각형 230,600개에서 6,704개로 줄며 간판·창틀 가장자리와 측면 창문이 손상됐다. 이 사례를 모든 생성 도구의 일반 성능으로 확대하지 않는다. 당시 소품 일괄 제작은 실행하지 않았다.

### 4.2 기존 배치·충돌을 보존한 NW03 외관 시제품

<a id="42-nw03-최초-외관-시제품"></a>

<a id="44-검증-결과와-한계"></a>

> 일자: 2026-10-12

- **문제**

	- 새 외관을 시험하면서 기존 몸체·옥상 구조·이동 충돌과 씬 배치를 보존해야 했다.

- **결정**

	| 항목 | 적용 방식 |
	|---|---|
	| 외관 | NW03 자식으로 추가, 기존 그레이박스 Renderer만 숨김 |
	| 형상 | 상자 125개, 삼각형 1,500개·정점 3,000개 |
	| 충돌 | 기존 1개 유지, 장식에는 추가하지 않음 |
	| 재질 | 소재별 8개 그룹으로 메시 통합 |
	| 저장 위치 | Assets/Art/Environment/NW03_Prototype/ |

	- 앞면 점포와 후면 관리용 문·환기구·배수관을 구분했다.

- **근거**

	- 기존 게임 공간을 바꾸지 않고 제작 결과를 비교하기 위한 방식이었다. 벽돌은 길이 기반 UV로 반복 크기를 맞췄다.

- **검증과 한계**

	- Unity 컴파일·제작 실행과 배치·충돌 보존을 확인했다. 창문은 벽 밖 평면과 돌출 프레임이며 개구부·내부를 제작한 상태는 아니다. Play 진입은 했으나 유효한 NW03 화면 캡처에 실패해 런타임 외관 검증 완료로 기록하지 않는다. 대상 빌드·프레임 시간·전체 반복 배치 성능은 미측정이었다.

### 4.3 편집 역할별 재질 분리

<a id="43-독립-재질-시험"></a>

> 일자: 2026-10-12

- **문제**

	- 초기 소재 묶음에서는 간판·점포 프레임·창틀·창턱·옥상을 따로 조절하기 어려웠다.

- **결정**

	- 기존 형상을 12개 편집 역할로 다시 묶고 MaterialStudyV2에 원본과 분리해 저장했다.

	| 역할 묶음 | 조절 의도 |
	|---|---|
	| 벽돌·옥상 콘크리트·창턱 석재 | 표면별 반복 질감 |
	| 유리·창틀·금속 부품 | 투명 표현과 금속 역할 분리 |
	| 차양 천 | 직조 표현 |
	| 두 점포 프레임·두 간판 | 독립 배색 |
	| 관리용 문·설비 | 도장 금속 |

	- 유리는 URP Unlit, 나머지는 Lit를 사용하고 노멀용 탄젠트를 계산했다.

- **근거**

	- 같은 소재라도 조절 목적이 다른 부분은 분리하고, 최초 형상과 비교할 수 있도록 원본은 보관했다.

- **검증과 한계**

	- 삼각형 위치 지문으로 형상 동일성을 확인했다.
	- 삼각형·정점 수는 같고 Renderer는 8개에서 12개로 늘었다.
	- 임시 카메라 렌더·구조 비교만 했으며 Play 외관 검증은 아니다.
	- 지정 입력색과 최종 픽셀 색 일치는 확인하지 않았다.
	- 사용자 화면에서 깊이·점포 차이·간판 정보 부족을 확인했고 최종 아트 합격으로 처리하지 않았다.

### 4.5 공유 소재와 건물별 외관 구성

<a id="45-소재-공유와-건물별-차이의-양립"></a>

<a id="410-후속-작업의-진입점과-검증-근거"></a>

> 일자: 최초 설계 2026-10-15, 적용 2026-10-16

- **문제**

	- 소재를 공유해 생산성을 높이면서도 건물별 연식·점포 차이를 유지해야 했다.

- **결정**

	- 같은 소재·표현에는 Material을 공유하고 독립 배색이 필요할 때 변형을 만들었다.
	- 창문 분할·층간 마감·차양·점포 프레임·후면 설비의 조합은 개별화했다.
	- NW02에서 확인한 뒤 기존 NW02·NW03 기본 외관을 유지하며 나머지 22채에 적용했다.
	- 외관 진입점은 GameScene의 BangiGraybox_160m 아래 건물별 BuildingArt_Polish01이며, 공유 재질은 NW03_Prototype/MaterialStudyV2와 Buildings/PolishPass01에서 확인한다(2026-10-16).

- **근거**

	- 블록별 외관 통일이나 NW03 복제는 건물별 차이를 줄인다. 재사용 단위를 건물 전체가 아닌 소재·편집 역할로 정했다.

- **검증과 한계**

	- 건물 24채·점포 23개에 적용했다. 일괄 작업은 기존 재질 8개와 공유 재질 16개를 사용했다. 돌출 간판은 형태·배색으로 표현하고 씬 글자는 제외했다. 공유 재질을 바꿀 때 참조 범위를 먼저 확인해야 하며, 원본 NW02 프리팹의 문자 제거는 씬 상태와 별개다. 사용자는 건물 작업 종료를 수용했으나 전체 맵 아트 합격을 확인한 것은 아니다.
	- 2026-10-16의 일괄 작업은 기존 배치·Transform·Collider·Camera·Light와 검사한 RenderSettings를 보존했고 새 장식에 충돌체를 추가하지 않았다.
	- 당시 추가 삼각형 75,128개는 전체 씬 비용이나 성능 합격선이 아니다. 실제 플레이 가독성·대상 빌드·성능은 미확인이다.
	- 작업 경계는 커밋 8f77a8b·f9320dc로 확인할 수 있으며 복구 전 이후 변경을 함께 확인해야 한다.

### 4.6 도로 질감의 UV·탄젠트와 반복 크기

<a id="46-노멀-효과를-판단하기-전-매핑-확인"></a>

> 일자: 2026-10-16

- **문제**

	- 도로에 질감을 넣어도 매끄럽게 보였고 메시에는 UV·탄젠트가 없었다.

- **결정**

	- UV를 (world X/2, world Z/2)로 만들고 탄젠트를 계산했다.
	- 색상·노멀 임포트 유형과 Repeat·밉맵·필터링을 설정했다.
	- Metallic 0·Smoothness 0.15·Normal 0.4를 출발점으로 Tiling 0.5를 선택했다.
	- 도로의 후속 편집 대상은 GB_Road.mat·Road_ContinuousIntersections.asset이며 UV 기준과 함께 확인한다(2026-10-16).

- **근거**

	- 재질 강도를 올리기 전에 올바른 좌표와 표면 방향 입력을 제공해야 했다. 2m 기준 UV에서 Tiling 0.5는 약 4m 반복이므로 질감 크기는 UV와 함께 판단해야 한다.

- **검증과 한계**

	- 정점 32개에 UV·탄젠트가 대응하고 정점 위치·삼각형·경계가 유지됨을 확인했다. 사용자가 큰 알갱이 외관을 수용했다. 이 수치는 다른 소재·UV의 공통 정답이 아니며 노멀은 실제 높이·실루엣을 만들지 않는다.

### 4.7 닫힌 연석 메시와 면 방향 정리

<a id="47-연석-음영과-반복-블록의-형상"></a>

> 일자: 2026-10-16

- **문제**

	- 열린 연석 메시가 얇은 판처럼 보이고 일부 구간에 이상한 그림자가 있었다.

- **결정**

	- 여섯 면이 닫힌 직육면체를 틈을 두고 반복했다.
	- 면 노멀이 중심에서 바깥을 향하는지 검사하고 단면 렌더링을 사용했다.
	- 실제 블록 경계와 중복되는 텍스처 줄눈·노멀을 제거했다.
	- Base Map 누락으로 중간 실패한 뒤 원래 상태를 확인하고 저장 텍스처를 직접 로드해 재적용했다.
	- 보도·연석의 후속 편집 대상은 SidewalkPolish01·Environment/Pavement에서 확인한다(2026-10-16).

- **근거**

	- 양면 렌더링은 열린 형상·뒤집힌 면의 올바른 음영을 보장하지 않는다. 메시 변경 전 필요한 재질·텍스처를 확인해야 중간 실패를 줄일 수 있다.

- **검증과 한계**

	- 블록 712개를 삼각형 8,544개의 한 메시로 구성하고 외곽을 유지했다. 구조 검사와 사용자 수정 수용을 확인했다. 당시 노멀 실시간 조회 실패로 모든 그림자 원인을 하나로 확정하지 않았으며, 모든 조명 조건의 합격을 뜻하지 않는다.

### 4.8 공통 바닥과 건물별 옥상 마감

<a id="48-공통-바닥과-옥상-변형의-적용-범위"></a>

> 일자: 2026-10-16

- **문제**

	- 바닥은 거리의 연결감을 유지하고 옥상은 한국 상가 요소를 건물마다 다르게 적용해야 했다.

- **결정**

	| 대상 | 선택 |
	|---|---|
	| 보도 | 공통 회색 작은 블록 |
	| 가게 앞 8구역 | 같은 계열 큰 판석과 기존 StoneSlabs 재사용 |
	| 옥상 | 10채에 저채도 초록 방수 두 변형, 14채 회색 유지 |
	| 옥상 설비 | 기존 계단실·난간 재사용, 12채에 단순 환기구 |

	- 몸체 높이로 지붕을 추정하지 않고 실제 수평 윗면을 찾았다.
	- 가게 앞 판석은 ShopFrontPaving01·StoneSlabs.mat, 옥상은 RoofFinish01·Environment/Rooftops에서 확인하며 기존 옥상 설비는 별도 계층이다(2026-10-16).

- **근거**

	- 가게마다 바닥 전체를 달리하면 길이 끊겨 보이고, 한국식 요소라는 이유로 모든 옥상에 같은 색·설비를 넣으면 개별성이 줄어든다. 기존 설비를 먼저 확인해 중복 생성도 피했다.

- **검증과 한계**

	- 바닥은 사용자 수용, 옥상은 구현·구조 검증까지 확인했다. 입구별 작은 타일·문턱은 제안만 있었고 만들지 않았다. 작업 종료 요청을 모든 옥상 외관의 개별 합격으로 해석하지 않는다.
	- 옥상 최종 외관·실제 플레이 가독성·대상 빌드·성능은 미확인이다. 바닥의 사용자 수용을 옥상의 개별 외관 합격으로 확대하지 않는다.

### 4.9 Unity 연결 실패 시 실행 상태 확인과 씬 보존

<a id="49-unity-실행-실패와-공유-상태-보존"></a>

> 일자: 2026-10-16

- **문제**

	- Unity 서버 실행 표시와 CLI 탐색·명령 완료가 일치하지 않고 연결 실패·시간 초과가 반복됐다.

- **결정**

	- 연결 표시·포트 응답·실제 명령 결과를 별개로 판단했다.
	- 오류 뒤 실제 변경 상태를 먼저 읽고 중복 생성 여부를 확인했다.
	- 미저장 공유 씬을 임의 저장·폐기·재로드하지 않았다.
	- 복구는 작업 대상에 한정하고 씬 전체를 과거 사본으로 덮어쓰지 않았다.

- **근거**

	- 시간 초과여도 명령이 일부 실행됐을 수 있다. 재시작·창 활성화·autotick의 일시 성공만으로 연결의 근본 원인이 해결됐다고 판단할 수 없었다.

- **검증과 한계**

	- 연결될 때 run_script, 연결되지 않을 때 임시 Editor 실행 경로로 API 적용에 성공했다. 재시작·활성화 후에도 실패가 재발했으며 근본 원인은 미확정이다. 추가 조사에는 같은 시점의 연결 정보·포트·Unity 로그 비교가 필요하다.
