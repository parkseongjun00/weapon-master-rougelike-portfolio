## 4. 첫 맵 건물 제작

### 4.1 제작 방식 전환

> 일자: 2026-10-12
> 상태: 사용자 확인, NW03 시제품 구현

건물 전체 자동 생성 시험을 거쳐, 사용자는 현재 배치와 그레이박스를 기반으로 Unity에서 단순한 건물 형태를 만들고 재질·점포 외관을 조정하는 방향을 선택했다.

- **텍스트 기반 건물 생성은 이번 제작 흐름에서 종료했다.**
	- 시험 결과에 주변 바닥·불필요한 글자·의도하지 않은 창문 및 지붕 표현이 포함되었다.
	- 사용자 결정에 따라 GPT로 앞·뒤 참고 이미지를 만들고 Meshy에 전달하는 시험으로 전환했다.
- **참고 이미지는 외관 검토와 제작 자료로 사용했다.**
	- 관리된 벽돌 몸체와 버건디·초록색 두 점포, 크림색 차양을 시험했다.
	- 앞면의 점포를 뒷면에 반복하지 않도록 후면 이미지를 별도로 제작했다.
	- 사용자가 유리를 `#91A6AD` 단색으로 지정하고 반사·그라데이션·내부 투시를 제외했다.
- **건물의 기본 구조는 단순 기하로 정확하게 제작한다.**
	- Meshy 최초 생성 모델에서 창문·차양·벽면이 뭉개지는 결과가 관찰되었다.
	- 사용자 제공 비교에서는 230,600 삼각형의 모델을 6,704 삼각형으로 줄인 뒤 창틀·간판 가장자리와 측면 창문이 손상되었다.
	- 최초 생성의 형태 손실과 리메시의 감량 손실을 구분하며, 관찰을 모든 생성 도구의 일반 성능으로 확대하지 않는다.
	- 사용자가 NW03 한 채를 기존 공간 구성에 맞춰 직접 제작하는 시험을 승인했다.
- **재질과 간판 교체를 중심으로 반복 제작한다.**
	- 사용자는 유리·창틀·천 등 의미 있는 요소의 재질을 독립적으로 조절하는 시험을 승인했다.
	- 간판 판의 앞면 이미지를 교체하고 작은 모델을 별도 제작·생성하는 방향을 확인했다.
	- 특정 소품의 일괄 생성이나 다른 건물의 확대 제작은 실행하지 않았다.

### 4.2 NW03 최초 외관 시제품

> 일자: 2026-10-12
> 상태: 구현, 형태·충돌 보존 확인

NW03 아래에 외관 메시를 추가하고 기존 그레이박스 렌더러만 숨기는 방식으로 시제품을 적용했다.

- **씬·재질·메시·프리팹은 Unity API로 생성하고 저장했다.**
- **현재 배치 스냅샷을 유지했다.**
	- 배치도 기준 NW03은 `(42, 39)`, 폭 20m, 깊이 26m, 2층이다.
	- Unity 몸체 중심은 `(-28, 3.15, 28)`, 크기는 `(20, 6.3, 26)`이다.
	- 남쪽 전면의 분식·국수 점포는 각각 시작 0.5m·10.5m, 폭 9m의 구획을 사용한다.
	- 기존 옥상 계단실·설비 매스의 위치와 크기를 유지했으며, 전체 실루엣 높이는 몸체 높이와 다르다.
- **외관은 상자 형태 125개로 구성했다.**
	- 상자당 삼각형 12개·면별 정점 24개로 총 삼각형 1,500개·정점 3,000개다.
	- 벽돌은 반복 텍스처로 표현하고 길이 기반 UV로 각 벽면의 크기를 맞춘다.
	- 앞면은 두 점포·창문·간판·차양, 뒷면은 작은 창문·관리용 문·환기구·배수관으로 구분했다.
	- 현재 유리는 벽 밖의 평면이고 프레임은 돌출 형태이며, 실제 창문 개구부와 내부 구조를 만든 상태는 아니다.
- **기존 공간과 충돌을 유지했다.**
	- 기존 충돌 1개를 유지하고 외관에는 충돌을 추가하지 않았다.
	- 다른 건물·카메라·통행 영역은 변경하지 않았다.
	- 기존 NW03 부품을 삭제하지 않고 렌더러를 숨겼다.
- **초기 재질은 8개로 묶었다.**
	- 벽돌·콘크리트·차양·알루미늄·설비·버건디·초록·유리별로 메시를 합쳤다.
	- 결과는 `Assets/Art/Environment/NW03_Prototype/`에 저장했다.

### 4.3 독립 재질 시험

> 일자: 2026-10-12
> 상태: 구현, 최초 형상 유지 확인

점포 프레임과 간판, 창틀과 금속 부품, 옥상과 창턱을 독립적으로 조절하도록 기존 삼각형을 재질 역할별로 다시 묶었다.

- **새 버전은 원본과 분리해 보관한다.**
	- 새 재질·메시·텍스처·프리팹은 `Assets/Art/Environment/NW03_Prototype/MaterialStudyV2/`에 저장했다.
	- 최초 재질·메시·프리팹은 보관했다.
- **12개 재질 역할을 구분했다.**

| 그룹 | 표현 |
|---|---|
| `BrickWall` | 벽돌 색 텍스처와 줄눈 노멀 |
| `RoofConcrete` | 옥상·난간벽·옥상 구조물의 콘크리트 |
| `WindowSillStone` | 창턱의 석재 |
| `WindowGlass` | 반사 없는 회청색 단색 |
| `WindowFrameAluminum` | 상층·측면·후면 창틀의 브러시드 금속 |
| `MetalHardware` | 손잡이·환기구·배수관 고정 부품 |
| `AwningFabric` | 크림색 차양의 직조 패턴 |
| `StoreFrameBurgundy` / `StoreFrameGreen` | 두 점포 프레임의 도장 |
| `SignBurgundy` / `SignGreen` | 두 간판의 도장 |
| `ServiceMetal` | 관리용 문·설비의 도장 금속 |

- **재질 입력을 분리했다.**
	- 유리는 URP Unlit의 지정색을 사용하고 나머지는 URP Lit를 사용한다.
	- 직조·브러시드 금속·도장·광물 패턴은 Unity에서 생성한 512×512 반복 텍스처와 노멀 맵으로 구성했다.
	- 역할별 색·Metallic·Smoothness·노멀 강도·반복 크기를 조절한다.
	- `#91A6AD`는 사용자 요청 입력색이며, 최종 화면의 픽셀 색 일치는 검증하지 않았다.
- **형상은 동일하게 유지했다.**
	- 삼각형 위치의 정렬된 지문을 비교해 재질 분리 전후의 일치를 확인했다.
	- 삼각형 1,500개·정점 3,000개는 유지되고 재질별 렌더러는 8개에서 12개로 늘었다.
	- 노멀 맵을 사용할 새 메시에는 탄젠트를 계산했다.
- **비주얼 완성도는 초벌 상태다.**
	- 현재 간판은 단색 재질이며 상호 이미지 적용은 시작하지 않았다.
	- 전체 건물 화면에서 미세한 질감 차이가 작게 보였다.
	- 사용자 제공 씬 화면에서 창문·출입구의 깊이, 두 점포의 차이와 간판 정보가 부족한 상태를 확인했다.
	- 재질 분리 구현과 최종 비주얼 합격은 구분한다.

### 4.4 검증 결과와 한계

> 일자: 2026-10-12
> 상태: 제작 실행·구조 검증 완료, 런타임 외관·성능 합격 미검증

씬·메시 비교로 시제품 작업의 범위를 확인했다. 임시 카메라의 렌더 이미지는 실제 Play Mode 화면 검증과 구분한다.

- **실행 전 컴파일을 검사했다.**
	- Unity에서 제작 작업을 실행할 때 컴파일 오류가 없었다.
	- 프로젝트 전체 테스트나 실행 빌드 통과를 의미하지 않는다.
- **변경 범위를 확인했다.**
	- 최초 작업은 NW03 자식 추가·기존 렌더러 숨김, 재질 작업은 시제품 내부 그룹 재분류·재질 교체로 한정되었다.
	- 기존 카메라·충돌은 동일하고 기존 씬 객체 삭제는 없었다.
- **Play Mode 실행과 캡처 한계를 구분했다.**
	- Play Mode 진입·종료를 실행하고 첫 확인에서 콘솔 오류가 없었다.
	- NW03 앞 화면 캡처 과정에서 Pipeline 명령 시간 초과와 저장 경로 오류가 발생했다.
	- 유효한 NW03 Play Mode 화면 검증 완료로 보고하지 않는다.
	- 재질 변경 후에는 임시 카메라 렌더와 구조 비교만 수행했다.
- **검토용 카메라는 촬영 뒤 제거했다.**
	- 게임 카메라의 저장 설정은 변경하지 않았다.
- **최종 성능과 아트 합격은 미확정이다.**
	- 실행 빌드·실기 프레임 시간·전체 건물 반복 배치 성능을 측정하지 않았다.
	- 건물당 최종 폴리곤·재질·텍스처 예산을 확정하지 않았다.
	- 후속 과제는 [Backlog 16](../Backlog.md#16-nw03-현실성-개선과-환경-리소스-검증)을 참고한다.

> 사용자 승인 범위에서 NW03 한 채의 제작 기반을 구현했다. 다른 건물 반복 제작과 후속 현실성 개선 실행은 별도 요청으로 정한다.

### 4.5 소재 공유와 건물별 차이의 양립

> 일자: 2026-10-16
> 최초 설계: 2026-10-15
> 상태: 사용자 결정, 전체 건물 적용 완료
> 비고: 사용자 요청으로 이번 이관 기록 4.5~4.10을 판단 근거와 재발 방지 중심으로 재구성했다.

같은 소재를 재사용하면서도 건물마다 연식과 점포 구성이 다른 한국 상가 거리를 표현해야 했다.

- **문제와 조건:** NW03을 그대로 복제하거나 블록마다 외관을 통일하면 건물별 차이가 줄어든다.
	- 사용자는 기존 건물별 디자인 방향을 수용하면서 생산성·일관성·품질을 함께 높이기를 요청했다.
- **선택과 이유:** 실제 소재는 공유하고 건물·점포의 조합은 개별화했다.
	- 벽돌·콘크리트·석재·유리·금속·천을 편집 역할로 구분했다.
	- 같은 표현에는 같은 Material을 지정하고 독립적인 배색이 필요할 때만 변형을 만들었다.
	- 창문 크기·분할, 층간 마감, 차양, 점포 프레임과 후면 설비를 달리해 같은 소재로도 다른 건물이 되게 했다.
- **적용 흐름:** NW02 치킨집에서 공유 가능성을 확인한 뒤 사용자가 나머지 건물의 일괄 적용을 승인했다.
	- NW02·NW03 기본 외관을 유지하고 22채에 새 외관을 적용했다.
	- 건물 24채·점포 23개에 적용했으며 일괄 작업의 재질 풀은 기존 8개와 새 공유 재질 16개였다.
	- 돌출 간판 15개는 형태·배색·브래킷으로 표현하고 씬의 글자는 제외했다.
	- 야간 발광·전역 조명은 이번 실행 범위에 포함하지 않았다.
- **다음 작업의 판단 기준:** 먼저 기존 소재·역할과 표현이 같은지 확인하고 재질을 공유한다.
	- 한 건물만 바꾸려면 공유 재질의 참조 범위를 먼저 확인하고 필요한 변형을 지정한다.
	- 실제로 이번 커밋에는 공유 NW03 벽돌·옥상 콘크리트의 Tiling 0.5 변경도 포함되었다.
	- 블록 이름만을 이유로 새 재질이나 동일한 외관을 만들지 않는다.
	- 원본 NW02 프리팹의 텍스트 제거 여부는 씬 상태와 별도로 확인해야 한다.

### 4.6 노멀 효과를 판단하기 전 매핑 확인

> 일자: 2026-10-16
> 상태: 도로 매핑 보완, 사용자 외관 수용

도로에 질감을 넣었지만 화면에서는 매끄럽게 보여, 재질 강도와 메시 입력을 구분해 확인해야 했다.

- **확인한 원인:** 기존 도로 메시에는 UV와 탄젠트가 빠져 있었다.
	- 노멀 강도만 조절해도 올바른 반복 좌표와 표면 방향 기준을 제공할 수 없는 상태였다.
- **수정과 이유:** 기존 지면 좌표로 UV를 만들고 탄젠트를 계산했다.
	- UV는 `(world X / 2, world Z / 2)`를 사용했다.
	- 정점 32개에 UV·탄젠트 32개가 대응하는지 확인하고 정점 위치·삼각형·경계는 보존했다.
	- 색상 텍스처는 Default, 노멀은 NormalMap으로 설정하고 Repeat·밉맵·Trilinear·Aniso 4를 적용했다.
- **사용자 선택:** Metallic 0·Smoothness 0.15·Normal 강도 0.4를 출발점으로 Tiling 0.5의 큰 알갱이 표현을 수용했다.
	- 2m 기준 UV에서 Tiling 0.5는 약 4m 반복이므로 알갱이가 커 보인다.
	- 이 수치는 다른 소재나 다른 UV를 가진 메시의 공통 정답이 아니다.
- **다음 작업의 확인 순서:** 텍스처 연결·노멀 임포트 유형, 메시 UV·탄젠트, 반복 크기를 확인한 뒤 광택과 노멀 강도를 조정한다.
	- 질감 크기는 Material의 Tiling 값만이 아니라 메시 UV의 기준 길이와 함께 판단한다.
	- 노멀 매핑은 표면의 빛 반응을 바꾸며 실제 실루엣이나 높이를 만드는 작업과 구분한다.

### 4.7 연석 음영과 반복 블록의 형상

> 일자: 2026-10-16
> 상태: 형상 정정·면 방향 검증 완료, 사용자 수정 결과 수용

최초 연석은 얇은 판처럼 보였고 사용자가 일부 구간의 이상한 그림자를 지적했다.

- **실패한 구성:** 윗면과 경사면만 생성한 열린 구조에 양면 렌더링을 사용했다.
	- 면 방향이 일관되지 않을 수 있는 생성 구조였으며 양면 표시만으로 올바른 음영을 보장하지 못했다.
	- 연석 질감에도 줄눈이 있어 실제 블록 경계와 별도의 무늬가 겹쳤다.
	- 실시간 노멀 조회가 실패했으므로 당시 모든 그림자 문제의 원인을 하나로 확정하지 않았다.
- **수정과 이유:** 여섯 면이 닫힌 직육면체를 좁은 틈을 두고 반복했다.
	- 기존 구간의 외곽을 사용해 배치를 유지하고 각 면의 노멀이 블록 중심에서 바깥을 향하는지 검사했다.
	- 전용 `GraniteCurb.mat`에서 줄눈·노멀 입력을 제거하고 회색 돌 질감과 단면 렌더링을 사용했다.
	- 블록 712개를 하나의 메시로 합쳐 삼각형 8,544개로 구성했다.
- **실행 중 추가 실패:** Material의 Base Map이 비어 있어 첫 수정이 메시 변경 뒤 중단되었다.
	- 되돌리기로 원래 정점 5,696개 상태를 확인한 뒤, 저장된 색상 에셋을 직접 로드하도록 수정해 재적용했다.
	- 재적용은 성공했지만 뒤이은 추가 조회는 시간 초과되었다.
- **다음 작업의 확인 기준:** 얇은 입체 반복물은 필요한 옆면·끝면과 바깥 방향을 갖춘 상태에서 음영을 판단한다.
	- 양면 렌더링을 뒤집힌 면의 해결책으로 사용하지 않는다.
	- 실제 블록 틈과 텍스처의 줄눈을 중복 표현하지 않는다.
	- 메시를 바꾸기 전에 필요한 재질·텍스처의 존재를 확인해 중간 실패를 줄인다.
	- 구조 검증과 사용자 화면 수용을 근거로 삼되 모든 조명 조건의 그림자 합격으로 확대하지 않는다.

### 4.8 공통 바닥과 옥상 변형의 적용 범위

> 일자: 2026-10-16
> 상태: 바닥 사용자 수용, 옥상 구현·구조 검증 완료

바닥은 거리의 연결감을 유지하고, 옥상은 한국 상가의 익숙한 요소를 건물별로 달리 적용해야 했다.

- **바닥 선택과 이유:** 일반 보도는 작은 회색 블록, 넓은 앞마당과 가게 앞은 같은 계열의 큰 판석을 사용했다.
	- 가게마다 전면 공간 전체를 다른 재질로 나누면 길이 조각처럼 끊겨 보일 수 있어 공통 바닥을 연결했다.
	- 가게 앞 8개 구역은 기존 `StoneSlabs.mat`을 재사용하고 삼각형 16개로 구성했다.
	- 입구별 작은 타일·문턱·벽 밑 마감 띠는 제안만 있었으며 구현하지 않았다.
- **옥상 선택과 이유:** 전 건물을 초록색으로 통일하지 않고 10채에 방수 바닥을 적용했다.
	- 채도가 낮은 초록색 재질 2종을 섞고 14채는 기존 회색을 유지했다.
	- 적용 건물은 NW01·NW03·NW06·NE03·NE05·SW01·SW03·SW06·SE02·SE04다.
	- 실제 기존 지붕의 가장 넓은 수평 윗면을 찾아 얇게 덧대어 몸체 높이만으로 바닥 위치를 추정하지 않았다.
- **구조물 선택과 이유:** 기존 계단실·난간을 재사용하고 12채에 직육면체 두 개로 만든 낮은 환기구를 추가했다.
	- 사용자는 Primitive로 어려운 구조물은 생략하고 출입구 추가 디테일 대신 옥상 작업으로 종료하기를 요청했다.
	- 기존 설비를 먼저 확인해 계단실을 중복 생성하지 않았다.
- **다음 작업의 판단 기준:** 연결되어야 하는 바닥과 건물별로 달라야 하는 표면을 구분해 재사용한다.
	- 한국식 요소라는 이유로 모든 건물에 같은 색과 설비를 배치하지 않는다.
	- 기존 지붕·난간·설비의 실제 높이와 구성부터 확인한다.
	- 사용자 종료·커밋 요청을 개별 옥상의 최종 외관 합격으로 해석하지 않는다.

### 4.9 Unity 실행 실패와 공유 상태 보존

> 일자: 2026-10-16
> 상태: API 적용 성공, CLI 불안정의 근본 원인 미확정

Unity에서 서버가 실행 중으로 표시되어도 CLI 연결 탐색 실패와 명령 시간 초과가 반복되었다.

- **관찰한 사실:** 7800 포트의 서버 표시, CLI 연결 가능 여부, 실제 명령 완료 여부가 항상 일치하지 않았다.
	- Editor 재시작·창 활성화 뒤 명령이 성공했지만 이후 다시 실패했다.
	- `set_autotick`이 켜져 있어도 안정적인 접속을 보장하지 못했다.
- **당시 우회:** 연결될 때는 `AgentScripts/`의 파일을 `run_script`로 실행했다.
	- 연결이 안 될 때는 임시 Editor 스크립트를 가져오기·컴파일 뒤 실행하는 경로를 사용했다.
	- 미저장 GameScene에서는 대기하고 사용자가 저장한 뒤 실행했다.
	- 생성 씬·에셋은 Unity API로 편집했으며 일회성 실행 소스는 사용 후 삭제했다.
- **판단 오류와 정정:** 단발 또는 몇 차례의 접속 성공만으로 연결이 해결되었다고 보고한 것은 근거가 부족했다.
	- 재시작·활성화는 관찰된 일시적 우회이며 확정된 원인이나 영구 해결책이 아니다.
	- 다음 조사에서는 연결 정보 파일, 포트 응답, Unity 로그를 같은 시점에 비교해야 원인을 좁힐 수 있다.
- **다음 작업의 보호 기준:** 명령 오류가 나면 실제 변경 상태를 읽기 전 같은 생성을 반복하지 않는다.
	- 시간 초과 응답만으로 명령이 전혀 실행되지 않았다고 가정하지 않는다.
	- 필요한 에셋과 씬 상태를 변경 전에 검사하고 재시도 시 중복 생성 여부를 확인한다.
	- 다른 세션과 공유하는 씬의 미저장 변경을 자동 저장·폐기·재로드하지 않는다.
	- 복구는 이번 작업의 대상에 한정하고 전체 씬을 예전 파일로 덮어쓰지 않는다.

### 4.10 후속 작업의 진입점과 검증 근거

> 일자: 2026-10-16
> 상태: 구현 로컬 커밋 완료, 임시 초안 이관
> 참고: `8f77a8b`, `f9320dc`

다음 작업에서는 아래 위치를 시작점으로 실제 참조와 최신 상태를 확인한다.

| 작업 | 씬·에셋 진입점 | 주의할 경계 |
|---|---|---|
| 건물 외관 | `GameScene.unity`의 활성 `BangiGraybox_160m`, 건물별 `BuildingArt_Polish01`, `Assets/Art/Environment/Buildings/PolishPass01/` | NW02·NW03은 기존 기본 외관을 함께 사용한다. |
| 공유 건물 재질 | `Assets/Art/Environment/NW03_Prototype/MaterialStudyV2/`, `Buildings/PolishPass01/` | 공유 재질 수정은 다른 건물에도 반영된다. |

- **보존 검증:** 장식 외관과 기존 이동·전투 구성을 분리했다.
	- 건물 일괄 적용에서는 몸체 배치와 생성 메시의 UV·탄젠트, 기존 Collider·Camera·Light와 검사한 RenderSettings 항목을 확인했다.
	- 연석 수정은 기존 도로·보도 메시·공유 재질·Collider, 전면 판석과 옥상 추가는 기존 Renderer·Collider의 직렬화 일치를 검사했다.
	- 새 바닥·연석·옥상 장식에는 충돌체를 추가하지 않았다.
	- 일괄 외관 로그의 추가 삼각형 75,128개는 전체 씬 비용이나 성능 합격선이 아니다.
- **완료 판정:** 구조 검사·사용자 수용·런타임 검증은 별개다.
	- 사용자는 아스팔트·건물 작업 종료·수정 연석·가게 앞 바닥을 수용했다.
	- 옥상 최종 외관·실제 플레이 가독성·실행 빌드 및 런타임 성능·전체 맵 최종 아트 합격은 별도 확인 대상이다.
	- 사용자 결정에 따라 이번에는 Codex의 외관 검사용 Play Mode·촬영·임시 렌더를 수행하지 않았다.
- **복구 근거:** 두 로컬 커밋으로 작업 경계를 남겼다.
	- `8f77a8b`는 건물·아스팔트·당시 임시 초안, `f9320dc`는 보도·연석·전면 판석·옥상을 포함한다.
	- 이 작업에서 두 커밋을 푸시하지 않았다.
	- 복구 시 해당 커밋 이후의 다른 작업을 확인하고 필요한 변경만 되돌린다.
- **문서 정리:** 임시 `Art/BuildingPolishingDraft.md` v0.2와 메타 파일은 확정 사항 이관 후 삭제했다.
	- 미채택 제작 계획을 확정된 구현으로 옮기지 않았다.
	- 빈 `Assets/Editor.meta`는 구현 커밋에서 제외했다.
