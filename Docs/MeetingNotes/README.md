# 회의록: 공통 규칙과 색인

> 공개 편집본 p3 · 2026-10-27 · 문서 원본 `37ba4c4`. 공개 범위와 코드 기준은 [문서 색인](../README.md)을 따른다.


회의에서 무엇을 고민하고 왜 선택·기각·유보했는지 되짚기 위한 스냅샷을 보존한다.

---

## 0. 일러두기

- **기록 성격**
	- 회의일을 문서의 현재 시점으로 삼는다. '당시'를 반복하거나 이후 결론에 맞춰 과거 판단을 고쳐 쓰지 않는다.
	- 사용자 의견·선택, AI 제안·이미지 실험, 채택 여부를 구분한다. 기록에 없는 이유·합의·논의 순서는 만들어 넣지 않는다.
	- 오기·사실관계·형식은 정정할 수 있다. 회의 후에 결정이 바뀐 경우에는 새로운 기록과 현재 기준 문서에서 관리한다.
	- 회의록은 실행 명세나 작업 목록이 아니다. 미정 의견을 백로그나 기준 문서로 자동 이관하지 않는다.
- **파일과 편집**
	- 회의록 파일명은 `NN-Topic-YYYYMMDD.md`로 정하고 번호는 생성 순서에 따른다.
	- 개별 회의록에는 회의일만 표시한다. 버전·수정일·변경 이력·일러두기는 두지 않고 편집 이력은 Git으로 확인한다.
	- WritingGuide의 표기·번호·구분선·문체를 기본 적용하되, 스냅샷 보존과 위 메타데이터 원칙은 이 규칙을 우선한다.

## 1. 문서 형식

| 위치 | 형식 | 내용 |
|---|---|---|
| 제목 | H1 | 회의 주제 |
| 날짜 | `- 회의일: YYYY-MM-DD` | 회의를 기준으로 한 날짜 |
| 안내 | 인용구 한 줄 | `YYYY-MM-DD 회의의 스냅샷입니다. 이후 결정이 변경되었을 수 있습니다.` |
| 요약 | 항목·요약의 2열 표 | 주제·선택·기각/유보·주요 이유·미정 사항. 해당 내용이 없는 행은 생략 |
| 본문 | 번호가 붙은 주제별 H2 | 주제 안에서 확인할 수 있는 논의·판단 변화 보존. 모든 회의에 같은 주제 목차를 강제하지 않음 |
| 내용 분류 | 굵은 상위 불릿 | 목표·방향·후보·시안 등 주제 안의 구분. 설명·표·이미지는 하위에 배치 |

- 비교는 표, 독립적인 요점은 불릿, 연결된 맥락은 짧은 문단으로 쓴다.
- 미정 사항은 선택적으로 모아두되, 다음 실행을 요구하는 필수 '할 일' 목차로 만들지 않는다.
