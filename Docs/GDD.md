> 공개 편집본 p1 · 2026-10-23 · 원본 `703affa`. 현재 안내는 [공개본 문서 색인](README.md)을 따른다. 과거 기록은 당시 상태이며 현재 코드 전체의 검증 결과가 아니다.

- 버전: v0.42
- 작성일: 2026-07-24
- 상태: 현장에서 싸울 수단을 확보·교체하는 콘셉트 반영. 코어 시스템 명세 디벨롭 중. 적 콘셉트·세계관 세부·비주얼 분위기·타이틀 미확정.

## 1. 개요

| 항목          | 내용                                     |
| ----------- | -------------------------------------- |
| 장르          | 로그라이트 (엔드리스 웨이브 서바이벌)                  |
| 시점          | 3D 쿼터뷰                                 |
| 조작 | 키보드 이동·마우스 조준·공격·상호작용 |
| 개발 환경       | Unity, 신규 Input System 사용              |
| 콘셉트 | 다양한 장소에서 주변의 무기와 무기로 쓰는 물건을 확보·교체하며 살아남는 즉흥 전투 |
| 세계관/타이틀/비주얼 | 적 콘셉트·사건·조직 설정·타이틀·비주얼 분위기는 별도 검토 |

- 플레이어는 현장에서 확보할 수 있는 싸울 수단을 바탕으로 다음 행동을 판단한다.
- 무기를 다루는 능숙함은 상황에 맞는 확보·사용·교체 판단으로 드러난다.
- 게임은 장소별 스테이지 확장을 지향한다. 한국 먹자골목은 첫 번째 스테이지이며 다른 장소의 구성과 수량은 미확정이다.
- '손에 잡히는 것이 무기가 된다'는 콘셉트는 무기로 지정한 물건의 획득·사용으로 구현한다. 모든 배경 오브젝트의 집기·투척·파괴는 별도 기능 검토 대상이다.
- 소개 방향은 장소와 돌발 상황을 먼저 제시해 플레이어가 자신의 행동을 상상하게 하는 것이다. 유입·공유 효과는 검증 과제다.

---

## 2. 디자인 목표

1. **급박한 상황에서의 즉흥 판단**: 정해진 최적 루트가 없고, 상황(적 구성, 남은 내구도, 주변 무기 배치)에 따라 매 순간 판단해야 한다.
2. **전투 매커니즘의 신속한 전환**: 근접↔원거리처럼 완전히 다른 조작감의 무기를 자주 갈아타야 한다.
3. **캐주얼함**: 판과 판 사이의 영향력을 최소화한다. 한 판 한 판이 무겁게 이어지지 않고 가볍게 즐길 수 있어야 한다.

## 3. 런(Run) 구조

- **엔드리스 웨이브 서바이벌**
	- 선택한 맵에서 시간이 지날수록 강해지는 적 웨이브를 상대한다.
	- **클리어(승리) 조건은 없다**.
	- 엔드리스 서바이벌이다.
	- 런은 플레이어 사망으로만 종료된다.
	- 런의 목표/성과 지표: **최대한 오래 생존** 또는 **최대한 많은 적 처치**.
		- 두 지표를 함께 기록.

- **맵 공간 구조**
	- 맵마다 제한형 또는 무한형 공간 구조를 선택한다.
	- 제한형 맵은 건물, 지형 또는 보이지 않는 벽으로 이동 범위를 제한한다.
	- 무한형 맵은 플레이어의 이동에 맞춰 공간이 계속 이어진다.
	- 첫 번째 맵은 핵심 전투와 공간 밀도를 먼저 검증하고 초기 제작 범위를 통제하기 위해 제한형으로 제작한다.
	- 첫 번째 맵은 전체 외곽 160×160m인 가상의 한국 먹자골목·상가 거리다.
	- 첫 번째 맵의 주요 전투 공간은 넓은 주 거리와 교차로이며, 짧은 지선과 코너 공간은 보조 공간이다. 건물 내부와 블록 안쪽 필지는 현재 플레이 공간이 아니다.
	- 무한형 맵은 포스트-MVP 콘텐츠로 검토한다.

> 참고: 던전 크롤 구조는 제작 부담으로 미채택. 완전히 폐기된 것은 아니며, 콘텐츠 다양성이 필요해지는 시점에 재고려될 여지를 남겨둔다.

## 4. 코어 루프

### 4.1 매크로 루프 (런 전체)

```
[런 시작: 맨손 상태로 선택한 맵에 스폰]
   → [진행: 전투·무기 관리·레벨업이 반복되며 난이도가 계속 상승 (반복 주기는 4.2 참고)]
   → [사망: 런 종료. 생존시간/처치수 기록 + 칭호/무기 도감 갱신]
[다음 런: 칭호/도감으로 쌓인 기록 반영해 반복. 판마다 크게 무겁지 않게]
```

---

### 4.2 마이크로 루프

1. 런 시작 즉시 맨손 상태로 시작한다.
2. 적이 사방에서 접근하면 이동하며 무기를 확보한다.
3. 장착한 무기로 공격하면 내구도가 소모된다.
4. 내구도가 임계치에 가까워지면 계속 쓸지, 다른 무기로 갈아탈지, 수동으로 버리고 재정비할지 판단한다.
5. 무기가 파괴되거나(내구도 0) 수동으로 드랍하면 맨손 상태로 전환된다.
6. 적을 처치하면 XP가 누적되고, 레벨업하면 증강을 선택한다.
7. 시간이 지날수록 적 물량/강도가 증가하며, 이 흐름이 사망까지 반복된다.

이 마이크로 루프가 게임의 전부다. 메타 진행/세계관은 이 루프를 반복할 동기를 부여하는 장치일 뿐이다.

## 5. 무기 시스템 명세

### 5.1 분류

| 분류 | 특징 |
|---|---|
| 근접형 | 사거리 짧음 |
| 원거리형 | 사거리 김, 투사체 기반 |

무기별 고유 정체성(빠르고 약한 무기, 느리고 강한 무기 등)은 무기 개체별로 스탯을 직접 정해 부여한다.

---

### 5.2 무기 스탯

| 스탯     | 설명                    | 우선순위                  |
| ------ | --------------------- | --------------------- |
| 공격력    | 타격당 데미지               | MVP                   |
| 공격속도   | 초당 공격 횟수              | MVP                   |
| 사거리    | 근접/원거리 구분의 핵심 수치      | MVP                   |
| 최대 내구도 | 파괴까지 남은 사용 횟수         | MVP                   |
| 중량     | 장착한 무기가 무거울수록 이동속도 감소 | 후순위(정식 채택, MVP 이후 개발) |
| 등급     | 동일 무기의 스탯 편차          | 후순위(정식 채택)            |

### 5.3 내구도 소모 규칙

| 무기    | 내구도 소모 시점 | 비고                    |
| ----- | --------- | --------------------- |
| 근접무기  | 명중 시 1 소모 | 헛스윙은 소모 없음            |
| 원거리무기 | 발사 시 1 소모 | 명중 여부 무관, 사실상 탄약처럼 작동 |

---

### 5.4 획득/버리기 규칙

- 시작 상태: **맨손**
- 장착 슬롯: **1개** (변경의 여지가 있음)
- 무기는 고정 스폰 포인트에서 주기적으로 스폰된다.
- **상호작용 버튼 하나**로 장착/교체/드랍을 모두 처리한다.
	- 바닥 무기 범위 안에서 누르면 장착한다. 손에 이미 무기가 있으면 그 무기를 플레이어 현재 위치에 드랍하고 교체하며, 맨손이면 그대로 장착한다.
	- 바닥 무기 범위 밖에서 누르면(손에 무기가 있을 때) 즉시 버리고 맨손이 된다.
	- 둘 다 아니면(맨손 + 범위 밖) 아무 일도 일어나지 않는다.
- 무기 파괴(내구도 0) 시 완전 소멸하고 맨손 상태(약한 기본 공격)로 전환된다.

---

### 5.5 등급(Rarity) 시스템

**등급은 무기 종류(정의)에 고정된 값이다.** 스폰마다 랜덤으로 결정되지 않으며, 설계(authoring) 시점에 이미 정해져 있다.

- 예: '방망이'는 항상 '일반' 등급으로만 존재한다.
- 필드에서 무작위인 건 '어떤 무기를 만나는가'와 '어떤 컨디션으로 만나는가'다.

**티어**: 일반 → 희귀 → 영웅 → 전설 (4단계)

**스탯 결정 방식** (2026-07-31 재정정): 등급별 최종 스탯(공격력/공격속도/최대내구도)은 런타임 공식으로 계산되지 않는다.

- 등급은 '총 스탯 예산이 대략 얼마인가'라는 가이드라인만 제공한다.
- 그 예산을 세 스탯에 어떻게 배분할지는 사람이 직접 정하거나(예: 화력형은 공격력 비중을 높게, 연사형은 공격속도 비중을 높게), 외부 밸런싱 도구가 계산해 반영한다.
- 그래서 '등급은 높은데 체감 가치는 낮은 개체'도 나올 수 있다. 이는 공식의 오류가 아니라 authoring 시점의 선택이다.

---

### 5.6 컨디션(Condition) 시스템

등급과는 별개로, 같은 무기·같은 등급이라도 스폰되는 개체마다 미세한 성능 편차를 주는 요소. **필드에서 실제로 무작위인 부분은 등급이 아니라 이 컨디션이다**.

- **적용 범위**: 공격력에만 영향을 준다. 최대내구도·공격속도에는 관여하지 않는다.
	- 내구도 편차는 체감 불공평함이 너무 크다.
	- 공격속도는 '개체 컨디션'이라는 개념과 어울리지 않는다고 판단해 제외했다.
	- 그러나 향후 테스트에 따라 판단이 달라질 수 있음을 인지해야 한다.

| 티어    | 배율   |
| ----- | ---- |
| 매우 나쁨 | -10% |
| 나쁨    | -5%  |
| 보통    | 0%   |
| 좋음    | +5%  |
| 매우 좋음 | +10% |


> 맨손(무기 미장착) 상태는 컨디션 적용 대상에서 제외된다.

## 6. 전투/적 시스템

### 6.1 적 유형

- 적의 정체성·외형·성격과 공격·피격·퇴장 표현은 디자인 검토 후 확정한다.

- 적은 유형별 공격 메커니즘으로 구분한다.
- 플레이어는 각 유형의 공격 조건·유효 시점·범위에 따라 피해를 받는다.

- **적 체력/사망 처리**
    - 적도 자체 HP를 가진다.
    - 플레이어 공격(근접 명중/원거리 투사체 명중)으로 데미지를 받아 HP가 0이 되면 사망하고 전투 대상에서 즉시 제거된다.
	- 퇴장 애니메이션이 있으면 이동·공격·피격 판정이 종료된 외형만 재생한 뒤 제거한다.
    - 퇴장 애니메이션이 없으면 외형도 즉시 제거한다.
    - 사망 즉시 사전 정의된 XP 값이 플레이어에게 가산된다.
	    - 이때 별도 XP 오브젝트는 스폰되지 않는다.
        - 이 흐름이 4.1의 '적 처치로 XP 획득' 루프다.
- **적 이동 알고리즘**
	- 대상 주변의 접근 슬롯을 적마다 예약하여 여러 방향에서 둘러싼다.
	- 슬롯은 대상별로 관리하며 플레이어·적의 구체 유형과 독립적으로 사용한다.
	- 안쪽 원이 차면 몸체 크기와 여유 간격으로 계산한 바깥 원의 슬롯을 추가하고, 안쪽 빈자리에는 바깥 참여자를 충원한다.
	- 도착 시 정지하고 대상이 이동하면 같은 자리를 재추적한다.
	- 적은 이동 가능한 영역의 경로를 따라 장애물을 우회하고 주변 개체를 회피한다. 도달할 수 없는 슬롯은 접근 실패로 보고하여 재배정한다.
	- 슬롯 점유는 접근 위치를 정하며, 공격 시작과 피해 판정은 유형별 공격 규칙을 따른다.
	- 슬롯 점유 자체는 공격 허가나 동시 공격 수 제한이 아니다.
	- 슬롯 수·원 반경은 대상·참여자의 몸체 반경과 여유 간격으로 계산한다. 접촉 보정·최대 원 수·분리 수치는 튜닝 대상이다.
	- 최대 수용량을 넘는 참여자는 안전 위치에서 대기하고 빈자리가 생기면 충원한다.
- **적 공격 방식**
	- 단순한 몸체 접촉은 공통 피해 조건이 아니다.
	- 유형별로 공격 시작 조건·예고·유효 시점·범위·방향 확정 시점·빗나감·공격 후 빈틈을 정한다.
	- 몸체 충돌로 피해를 주는 공격은 해당 유형에 정의한 활성 상태와 판정 조건에서만 적용한다.
	- 피해량·공격 간격·동일 공격의 중복 피해 조건은 유형별로 정한다.
	- 몸체 충돌·개체 간 분리와 공격 피해 판정은 구분한다.
	- 설계 사유: 적의 행동을 보고 회피·접근·반격을 선택하고, 공격을 피한 뒤의 빈틈을 활용할 수 있도록 한다.
	- 기본 적은 사거리에서 정지하고 방향을 확정한 뒤 한 손 펀치를 사용한다.
	- 기본 펀치는 피해8·목표 공격 간격1초·시작 거리1.35m를 초기 조정값으로 사용한다.
	- 별도 예고 제작 전에는 기존 펀치의 준비 구간을 사용한다.
	- 손 판정이 활성인 동안 접촉한 플레이어에게 공격당 최대1회 피해를 주며, 빗나가도 모션 종료까지 재생한다.
	- 공격 후 모션 종료와 공격 간격 조건을 모두 만족하면 다시 공격할 수 있다.
- **적 스폰 위치**
    - 제한형 맵은 맵 경계 부근에서 플레이어와 일정 거리 이상 떨어진 지점을 선택한다.
    - 무한형 맵은 플레이어 주변의 활성 범위에서 일정 거리 이상 떨어진 지점을 선택한다.
    - 플레이어 바로 옆에서 적이 갑자기 나타나지 않도록 보장한다.
    - 몸체가 맵 안의 보행 바닥 위에 있고 장애물·캐릭터와 겹치지 않는 위치에 생성한다.
    - 한 주기의 후보가 모두 실패하면 생성하지 않고 다음 스폰 주기로 넘긴다.

| 적 유형       | 특징         |
| ---------- | ---------- |
| 다수/저체력 스웜형 | 근접해서 둘러쌈   |
| 방어형/고체력 단일 | 느리지만 맷집 높음 |
| 원거리 견제형    | 거리 유지하며 공격 |

이 표는 역할 후보이며 개별 유형의 채택을 뜻하지 않는다.

---

### 6.2 난이도 곡선 (엔드리스)

- 목표: 최대 생존시간 / 최대 처치수. 승리 조건 없음.
- 시간 경과에 따라 동시 스폰 적 수, 스폰 주기가 계속 증가.
- (포스트-MVP) 적 강도(체력/공격력) 스케일링, 적 유형의 대량 확대.
- 세부 수치는 별도 밸런스 시트에서 관리.

---

### 6.3 조작

- **현재 입력**
	- 이동은 WASD/방향키
	- 조준은 **마우스 커서 방향** (캐릭터가 커서를 바라봄)
	- 클릭 또는 별도 키로 공격 실행.

이전 초안의 '자동 타겟팅' 방식은 폐기하고 수동 조준으로 대체. 약간의 조준 보정(자동 스냅/자석 효과)은 후순위 옵션으로만 열어둠(11장).

- 줍기/교체/드랍: 상호작용 버튼 하나로 처리(5.4 참고).

---

### 6.4 데미지 판정 방식

- **근접무기**: 활성 타격 구간에 Collider가 접촉한 여러 대상에게 각각 공격당 1회 피해를 준다.
  - 로그라이크 장르 특성상 다수의 적을 상대해야 하므로, 근접무기가 단일 타겟만 때리면 존재 의미가 크게 줄어든다.
- **원거리무기**: 투사체는 **최초로 명중한 적에게만** 데미지를 주고 소멸한다(관통/피어싱 없음).
  - 관통 같은 특수 속성은 이후 무기 다양성을 넓힐 때 개별 무기의 차별점으로 남겨둔다(포스트-MVP).

## 7. 진행/보상 구조

### 7.1 런 내

- **XP 획득**
	- 적 처치 시 XP를 획득한다.
	- 적 사망 즉시 사전 정의된 XP 값이 플레이어에게 곧바로 가산된다.
		- 별도 XP 오브젝트는 필드에 스폰되지 않는다.

- **레벨업 & 증강**
	- XP가 누적되어 레벨업하면 즉시 최대 체력으로 회복하고, 증강 3종 중 1개를 선택한다.
	- 증강 선택 팝업이 떠 있는 동안 게임은 일시정지된다.
		- 급박한 전투 중 선택을 강요해 판단 압박을 더하기보다, 선택 자체에 집중할 수 있게 하기 위함이다.
	- **증강 성장 방식: 레벨링**
		- 같은 증강을 여러 번 선택할 수 있고, 선택할 때마다 레벨이 오른다.
		- 각 증강은 Max레벨을 가지며, 레벨별 효과 크기는 증강마다 다르게 정의할 수 있다(어떤증강은 1레벨에 크게, 어떤 증강은 점진적으로).
		- Max레벨에 도달한 증강은 이후 3택 후보 풀에서 제외된다.
		- 레벨별 총 효과는 표로 정의한다.
	- XP 곡선(레벨별 Max레벨 수치, 레벨당 효과 크기 포함)은 별도 밸런스 시트에서 관리한다.
	- 증강 등장 확률은 동일하다.

> **1차 목록 확정 (2026-07-27)**: 공격력 증가, 공격속도 증가, 이동속도 증가, 최대체력 증가.


- **런 기록 표시**
	- 생존시간/처치수를 실시간 HUD로 표시하고, 사망 시점의 값을 로컬에 저장한다
	- 저장된 값을 보여주는 결과 화면은 범위 밖이며, 별도로 구현된다.
	- 여기서는 데이터를 실시간 표시하고 저장해두는 것까지만 다룬다.

---

### 7.2 런 간 (메타 진행)

**'가볍게, 판마다 크게 영향 주지 않기'** 원칙은 유지하되, 구체적인 구현 방식은 논의를 거쳐 아래와 같이 재확정됐다. **메타 진행은 런 내 파워에 절대 영향을 주지 않는다**.

이전 v0.3에서 확정했던 '신규 무기 종류 해금·신규 무기 등급 해금·코스메틱' 3축은 **폐기**한다. 해금 방식은 확률 스폰과 결합하면 '돈 냈는데 이번 런엔 안 나온다' 따위의 좌절감을 준다. 그래서 **무기 종류는 처음부터 전부 순수 확률로 조우 가능**하게 한다(등급은 무기 종류에 고정된 값이라 별도로 확률에 좌우되지 않는다. 5.5 참고). 코스메틱은 비주얼 아트가 보류 상태라 투자 대비 효과가 낮아 제외한다.

**메타 진행은 다음 두 축으로 재구성한다. 조건 달성 시 곧바로 부여되는 방식이다.**

- **칭호(타이틀)**: 특정 조건(누적 처치수, 생존시간, 특정 등급 무기 최초 획득 등) 달성 시 화폐 교환 없이 곧바로 해금되는 도전과제형 칭호. 파워에 영향 없음, 순수 과시/기록용.
- **무기 도감**: '무기 종류 × 등급' 조합을 실제로 필드에서 조우(발견)할 때마다 도감에 기록. 화폐 없이 발견 자체가 진행 조건이라는 원칙은 유지된다.

  > **재검토 필요**: 이 절을 쓸 당시엔 등급도 필드 조우 확률로 정해진다고 전제했다. 5.5가 '등급은 무기 종류에 고정'으로 정정되며 이 전제가 깨졌다. 현재 무기가 2종뿐이라 '무기 종류 × 등급' 조합 중 실제 도달 가능한 칸이 제한적이다. 칭호의 '특정 등급 무기 최초 획득' 조건도 마찬가지로, 그 등급을 가진 무기 종류가 로스터에 있어야만 달성 가능하다. 상세 현황은 11장 참고.

**콘텐츠 볼륨은 의도적으로 최소화한다.** 칭호를 의미 있게 만들려면 최소 30개 안팎, 도감도 20개 이상 항목이 필요해 보이지만, 이 프로젝트의 목적 대비 과잉 투자로 판단해 **시스템(조건 트리거·저장·표시 구조)만 다지고 콘텐츠는 최소 세트만** 채운다. 콘텐츠가 실제로 늘어나면 볼륨을 자연스럽게 확장한다.

생존시간/처치수는 기존대로 기록/랭킹 성격으로 활용해 '비교하는 재미'는 주되, 파워 이득으로 직결시키지 않는다.

## 10. MVP 범위 정의 (개발 착수 기준)

> 초기 착수 범위 기록이다. 현재 구현 여부를 나열한 표가 아니며, 이후 확정된 규칙은 각 본문 절을 따른다.

**포함**
- 제한형 첫 맵에서 진행하는 엔드리스 서바이벌
- 근접/원거리 2종(확장 가능한 데이터 구조로 구현)
- 내구도 소모: 근접=명중 시, 원거리=발사 시
- 무기 슬롯 1개, 필드 스폰 + 상호작용 버튼으로 획득·교체·드랍
- 맨손 시작
- 유형별 공격 메커니즘을 사용하는 적(6.1 참고, 첫 유형·수량은 미확정)
- XP/레벨업 + 3택 증강 시스템(전역 스탯 적용)
- 키보드 이동·마우스 조준·공격·상호작용 입력
- 칭호(타이틀)·무기 도감 최소 세트 (화폐 없이 조건/발견 기반, 파워 무관. 7.2 참고)

**제외 (후순위)**
- 무기 등급/희귀도, 이동속도 페널티, 슬롯 확장
- 3번째 이상 무기 대분류
- 적 유형의 대량 확대(6.1의 개별 역할 후보는 별도 채택)
- 무기 특화 증강
- 조준 자동 보정(스냅/자석)
- 스토리/세계관/최종 아트, UI 폴리싱
- 무한형 맵

## 11. 열린 질문

메타 진행 설계 원칙(구 1번)은 7.2에서 확정되어 제거함. 아래 항목들은 모두 **개발 초기 구조를 막지 않는 튜닝/구현 세부사항**으로, 지금 당장 결정할 필요 없이 해당 시스템을 실제로 만들 때 또는 플레이테스트하면서 판단해도 된다.

1. XP 곡선 및 레벨당 증강 후보 목록/확률 밸런스.
2. 무기별 타격 Collider의 크기와 활성 구간 튜닝. 활성 구간 접촉 판정은 구현됨.
3. 원거리 투사체 속도/히트박스 규격.
4. 조준 자동 보정(스냅) 도입 여부 및 시점.
5. 적 스폰 강도 곡선(시간 함수) 구체값.
6. 배포 방식과 일정은 별도 검토.
7. 무기 3번째 대분류 도입 시점/필요성.
8. 무기 내구도 증가 증강의 채택 여부 및 세부 규칙(소급 적용 여부 등). 보류 중이며 추가 고민이 필요하다.
9. 증강별 Max레벨 수치와 레벨별 효과 크기 구체값. 7.1에서 구조는 확정되었으나 수치는 튜닝 대상이다.
10. 칭호/무기 도감의 최종 목록과 개수. 콘텐츠 볼륨은 의도적으로 최소화했고(최소 세트만), 콘텐츠가 늘어나면서 확장 시점·규모를 재검토한다.
11. 무기 도감/칭호의 '등급도 필드 조우 확률' 전제가 5.5 정정으로 깨진 문제(배경은 7.2 참고). **칭호는 해결됨(2026-07-31)**: '특정 등급 무기 최초 획득' 조건을 '컨디션이 매우 좋음(VeryGood)으로 스폰된 무기 최초 획득'으로 교체했다(컨디션은 스폰마다 실제로 랜덤 결정되므로 전제가 성립). **도감 슬롯 구성은 여전히 미해결이며 재설계가 필요하다.**
