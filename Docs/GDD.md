# 웨폰마스터 로그라이크 게임 디자인 문서

- 버전: v0.29
- 상태: 코어 시스템 명세 디벨롭 중. 세계관/비주얼/타이틀 확정 전.

---

## 1. 개요

| 항목 | 내용 |
| ----------- | -------------------------------------- |
| 장르 | 로그라이트 (엔드리스 웨이브 서바이벌) |
| 시점 | 3D 쿼터뷰 |
| 타겟 플랫폼 | 웹(WebGL) 우선 개발 → 모바일 이식 |
| 조작 | PC(마우스/키보드) 우선 구현 → 이후 모바일 터치(트윈스틱) 대응 |
| 개발 환경 | Unity, 신규 Input System 사용 |
| 세계관/타이틀/비주얼 | 코어 루프 검증 후 결정 |

---

## 2. 디자인 목표

1. **급박한 상황에서의 즉흥 판단**: 정해진 최적 루트가 없고, 상황(적 구성, 남은 내구도, 주변 무기 배치)에 따라 매 순간 판단해야 한다.
2. **전투 매커니즘의 신속한 전환**: 근접↔원거리처럼 완전히 다른 조작감의 무기를 자주 갈아타야 한다.
3. **캐주얼함**: 판과 판 사이의 영향력을 최소화한다. 한 판 한 판이 무겁게 이어지지 않고 가볍게 즐길 수 있어야 한다.

---

## 3. 런(Run) 구조

- **단일 아레나 엔드리스 웨이브 서바이벌**
	- 고정된 하나의 아레나에서 시간이 지날수록 강해지는 적 웨이브를 상대한다.
	- **클리어(승리) 조건은 없다**.
	- 엔드리스 서바이벌이다.
	- 런은 플레이어 사망으로만 종료된다.
	- 런의 목표/성과 지표: **최대한 오래 생존** 또는 **최대한 많은 적 처치**.
 - 두 지표를 함께 기록.

- **아레나 형태/경계**: 사각형 또는 원형의 열린 평면 하나, 보이지 않는 벽으로 이동 범위를 제한한다. 정확한 크기·형태는 비주얼/세계관이 확정되는 단계에서 다시 잡을 수 있으므로, 그 전까지는 스케일 검증용 임시값을 사용한다.

> 참고: 던전 크롤 구조는 제작 부담으로 미채택. 완전히 폐기된 것은 아니며, 콘텐츠 다양성이 필요해지는 시점에 재고려될 여지를 남겨둔다.

## 4. 코어 루프

### 4.1 매크로 루프 (런 전체)

```
[런 시작: 맨손 상태로 아레나에 스폰]
 → [진행: 전투·무기 관리·레벨업이 반복되며 난이도가 계속 상승 (반복 주기는 4.2 참고)]
 → [사망: 런 종료. 생존시간/처치수 기록 + 칭호/무기 도감 갱신]
[다음 런: 칭호/도감으로 쌓인 기록 반영해 반복. 판마다 크게 무겁지 않게]
```

---

### 4.2 마이크로 루프

1. 런 시작 즉시 맨손 상태로 시작한다.
2. 적이 사방에서 접근하면 이동하며 무기를 확보한다.
3. 장착한 무기로 공격하면 내구도가 소모된다.
4. 내구도가 임계치에 가까워지면 계속 쓸지, 다른 무기로 갈아탈지, 수동으로 버리고 재정비할지 판단한다.
5. 무기가 파괴되거나(내구도 0) 수동으로 드랍하면 맨손 상태로 전환된다.
6. 적을 처치하면 XP가 누적되고, 레벨업하면 증강을 선택한다.
7. 시간이 지날수록 적 물량/강도가 증가하며, 이 흐름이 사망까지 반복된다.

이 마이크로 루프가 게임의 전부다. 메타 진행/세계관은 이 루프를 반복할 동기를 부여하는 장치일 뿐이다.

## 5. 무기 시스템 명세

### 5.1 분류

| 분류 | 특징 |
|---|---|
| 근접형 | 사거리 짧음 |
| 원거리형 | 사거리 김, 투사체 기반 |

무기별 고유 정체성(빠르고 약한 무기, 느리고 강한 무기 등)은 무기 개체별로 스탯을 직접 정해 부여한다.

---

### 5.2 무기 스탯

| 스탯 | 설명 | 우선순위 |
|---|---|---|
| 공격력 | 타격당 데미지 | MVP |
| 공격속도 | 초당 공격 횟수 | MVP |
| 사거리 | 근접/원거리 구분의 핵심 수치 | MVP |
| 최대 내구도 | 파괴까지 남은 사용 횟수 | MVP |
| 중량 | 장착한 무기가 무거울수록 이동속도 감소 | 후순위(정식 채택, MVP 이후 개발) |
| 등급 | 동일 무기의 스탯 편차 | 후순위(정식 채택) |

---

### 5.3 내구도 소모 규칙

| 무기 | 내구도 소모 시점 | 비고 |
|---|---|---|
| 근접무기 | 명중 시 1 소모 | 헛스윙은 소모 없음 |
| 원거리무기 | 발사 시 1 소모 | 명중 여부 무관, 사실상 탄약처럼 작동 |

---

### 5.4 획득/버리기 규칙

- 시작 상태: **맨손**
- 장착 슬롯: **1개** (변경의 여지가 있음)
- 무기는 고정 스폰 포인트에서 주기적으로 스폰된다.
- 새 무기 콜라이더에 닿으면 기존 장착 무기를 플레이어 현재 위치에 자동으로 드랍하고, 새 무기를 장착한다.
- **수동 드랍 버튼**: 언제든 누르면 즉시 무기를 버리고 맨손이 될 수 있는 전용 버튼이다.
- 무기 파괴(내구도 0) 시 완전 소멸하고 맨손 상태(약한 기본 공격)로 전환된다.

---

### 5.5 등급(Rarity) 시스템

**등급은 무기 종류(정의)에 고정된 값이다.** 스폰마다 랜덤으로 결정되지 않으며, 설계(authoring) 시점에 이미 정해져 있다.

- 예: '방망이'는 항상 '일반' 등급으로만 존재한다.
- 필드에서 무작위인 건 '어떤 무기를 만나는가'와 '어떤 컨디션으로 만나는가'다.

**티어**: 일반 → 희귀 → 영웅 → 전설 (4단계)

**스탯 결정 방식** (재정정): 등급별 최종 스탯(공격력/공격속도/최대내구도)은 런타임 공식으로 계산되지 않는다.

- 등급은 '총 스탯 예산이 대략 얼마인가'라는 가이드라인만 제공한다.
- 그 예산을 세 스탯에 어떻게 배분할지는 사람이 직접 정하거나(예: 화력형은 공격력 비중을 높게, 연사형은 공격속도 비중을 높게), 외부 밸런싱 도구가 계산해 반영한다.
- 그래서 '등급은 높은데 체감 가치는 낮은 개체'도 나올 수 있다. 이는 공식의 오류가 아니라 authoring 시점의 선택이다.

---

### 5.6 컨디션(Condition) 시스템

등급과는 별개로, 같은 무기·같은 등급이라도 스폰되는 개체마다 미세한 성능 편차를 주는 요소. **필드에서 실제로 무작위인 부분은 등급이 아니라 이 컨디션이다**.

- **적용 범위**: 공격력에만 영향을 준다. 최대내구도·공격속도에는 관여하지 않는다.
	- 내구도 편차는 체감 불공평함이 너무 크다.
	- 공격속도는 '개체 컨디션'이라는 개념과 어울리지 않는다고 판단해 제외했다.
	- 그러나 향후 테스트에 따라 판단이 달라질 수 있음을 인지해야 한다.

| 티어 | 배율 |
| ----- | ---- |
| 매우 나쁨 | -10% |
| 나쁨 | -5% |
| 보통 | 0% |
| 좋음 | +5% |
| 매우 좋음 | +10% |

> 맨손(무기 미장착) 상태는 컨디션 적용 대상에서 제외된다.

## 6. 전투/적 시스템

### 6.1 적 유형

- MVP는 **단일 범용 적 하나**로 시작한다.
- 플레이어에게 접촉 시 HP가 감소한다.

- **적 체력/사망 처리**
	- 적도 자체 HP를 가진다.
	- 플레이어 공격(근접 명중/원거리 투사체 명중)으로 데미지를 받아 HP가 0이 되면 사망하고 필드에서 제거된다.
	- 사망 즉시 사전 정의된 XP 값이 플레이어에게 가산된다.
 	- 이때 별도 XP 오브젝트는 스폰되지 않는다.
 	- 이 흐름이 4.1의 '적 처치로 XP 획득' 루프다.
- **적 이동 알고리즘**
 	- 다수의 적이 동시에 스폰되므로, 단순히 직선으로 몰려들게 하면 서로 겹쳐 뭉치는 문제가 생기기 쉽다.
 	- Boids 알고리즘 중 개체 간 간격을 유지하는 separation 규칙을 적용하는 것을 채택 방향으로 검토한다.
 	- cohesion/alignment 등 나머지 Boids 규칙은 굳이 필요 없을 수 있다.
 	- 목표는 플레이어를 향해 몰려들되 서로 겹치지 않는 것이다.
 	- 구체적인 파라미터(분리 반경, 가중치 등)는 구현 시 튜닝한다.
- **적 공격 방식**
 	- 접촉 즉시 1회성 데미지가 아니라, 접촉이 유지되는 동안 일정 쿨다운마다 반복 데미지를 준다(예: N초마다 1회).
 	- 그렇지 않으면 스치기만 해도 큰 피해를 입거나, 지속 접촉 시 순식간에 사망하는 극단적 상황이 생기기 쉽다.
 	- 정확한 쿨다운 값은 튜닝 대상이다(11장 참고).
- **적 스폰 위치**
 	- 아레나 경계 부근, 플레이어로부터 일정 거리 이상 떨어진 지점에서 무작위로 스폰한다.
 	- 플레이어 바로 옆에서 적이 갑자기 나타나는 것을 방지하기 위함이다.

| 적 유형 | 특징 |
| ---------- | ---------- |
| 다수/저체력 스웜형 | 근접해서 둘러쌈 |
| 방어형/고체력 단일 | 느리지만 맷집 높음 |
| 원거리 견제형 | 거리 유지하며 공격 |

이 확장안은 코어 루프가 검증된 후, 재미 기둥 1을 더 강화하고 싶을 때 도입을 고려.

---

### 6.2 난이도 곡선 (엔드리스)

- 목표: 최대 생존시간 / 최대 처치수. 승리 조건 없음.
- 시간 경과에 따라 동시 스폰 적 수, 스폰 주기가 계속 증가.
- (포스트-MVP) 적 강도(체력/공격력) 스케일링, 적 유형 다양화.
- 세부 수치는 별도 밸런스 시트에서 관리.

---

### 6.3 조작

- **모바일**
	- 좌측 가상 조이스틱(이동) + 우측 가상 조준 스틱(조준 방향 지정).
	- 원거리 무기: 조준 스틱이 가리키는 방향으로 투사체 발사.
	- 근접 무기: 조준 방향으로 짧은 사거리 판정(부채꼴/직선) 스윙.
- **웹(PC)**
	- 이동은 WASD/방향키
	- 조준은 **마우스 커서 방향** (캐릭터가 커서를 바라봄)
	- 클릭 또는 별도 키로 공격 실행.

이전 초안의 '자동 타겟팅' 방식은 폐기하고 수동 조준으로 대체. 약간의 조준 보정(자동 스냅/자석 효과)은 후순위 옵션으로만 열어둠(11장).

- 줍기: 자동(무기 위 이동 시).
- 드랍: 전용 버튼(5.4).

---

### 6.4 데미지 판정 방식

- **근접무기**: 판정 범위(사거리) 내에 있는 **모든 적을 동시에 타격**(다중 히트)한다.
 - 로그라이크 장르 특성상 다수의 적을 상대해야 하므로, 근접무기가 단일 타겟만 때리면 존재 의미가 크게 줄어든다.
- **원거리무기**: 투사체는 **최초로 명중한 적에게만** 데미지를 주고 소멸한다(관통/피어싱 없음).
 - 관통 같은 특수 속성은 이후 무기 다양성을 넓힐 때 개별 무기의 차별점으로 남겨둔다(포스트-MVP).

## 7. 진행/보상 구조

### 7.1 런 내

- **XP 획득**
	- 적 처치 시 XP를 획득한다.
	- 적 사망 즉시 사전 정의된 XP 값이 플레이어에게 곧바로 가산된다.
 - 별도 XP 오브젝트는 필드에 스폰되지 않는다.

- **레벨업 & 증강**
	- XP가 누적되어 레벨업하면 즉시 최대 체력으로 회복하고, 증강 3종 중 1개를 선택한다.
	- 증강 선택 팝업이 떠 있는 동안 게임은 일시정지된다.
 - 급박한 전투 중 선택을 강요해 판단 압박을 더하기보다, 선택 자체에 집중할 수 있게 하기 위함이다.
	- **증강 성장 방식: 레벨링
 - 같은 증강을 여러 번 선택할 수 있고, 선택할 때마다 레벨이 오른다.
 - 각 증강은 Max레벨을 가지며, 레벨별 효과 크기는 증강마다 다르게 정의할 수 있다(어떤증강은 1레벨에 크게, 어떤 증강은 점진적으로).
 - Max레벨에 도달한 증강은 이후 3택 후보 풀에서 제외된다.
 - 레벨별 총 효과는 표로 정의한다.
	- XP 곡선(레벨별 Max레벨 수치, 레벨당 효과 크기 포함)은 별도 밸런스 시트에서 관리한다.
	- 증강 등장 확률은 동일하다.

> **1차 목록 확정 **: 공격력 증가, 공격속도 증가, 이동속도 증가, 최대체력 증가.

- **런 기록 표시**
	- 생존시간/처치수를 실시간 HUD로 표시하고, 사망 시점의 값을 로컬에 저장한다
	- 저장된 값을 보여주는 결과 화면은 범위 밖이며, 별도로 구현된다.
	- 여기서는 데이터를 실시간 표시하고 저장해두는 것까지만 다룬다.

---

### 7.2 런 간 (메타 진행)

**'가볍게, 판마다 크게 영향 주지 않기'** 원칙은 유지하되, 구체적인 구현 방식은 논의를 거쳐 아래와 같이 재확정됐다. **메타 진행은 런 내 파워에 절대 영향을 주지 않는다**.

이전 v0.3에서 확정했던 '신규 무기 종류 해금·신규 무기 등급 해금·코스메틱' 3축은 **폐기**한다. 해금 방식은 확률 스폰과 결합하면 '돈 냈는데 이번 런엔 안 나온다' 따위의 좌절감을 준다. 그래서 **무기 종류는 처음부터 전부 순수 확률로 조우 가능**하게 한다(등급은 무기 종류에 고정된 값이라 별도로 확률에 좌우되지 않는다. 5.5 참고). 코스메틱은 비주얼 아트가 보류 상태라 투자 대비 효과가 낮아 제외한다.

**메타 진행은 다음 두 축으로 재구성한다. 조건 달성 시 곧바로 부여되는 방식이다.**

- **칭호(타이틀)**: 특정 조건(누적 처치수, 생존시간, 특정 등급 무기 최초 획득 등) 달성 시 화폐 교환 없이 곧바로 해금되는 도전과제형 칭호. 파워에 영향 없음, 순수 과시/기록용.
- **무기 도감**: '무기 종류 × 등급' 조합을 실제로 필드에서 조우(발견)할 때마다 도감에 기록. 화폐 없이 발견 자체가 진행 조건이라는 원칙은 유지된다.

 > **재검토 필요**: 이 절을 쓸 당시엔 등급도 필드 조우 확률로 정해진다고 전제했다. 5.5가 '등급은 무기 종류에 고정'으로 정정되며 이 전제가 깨졌다. 현재 무기가 2종뿐이라 '무기 종류 × 등급' 조합 중 실제 도달 가능한 칸이 제한적이다. 칭호의 '특정 등급 무기 최초 획득' 조건도 마찬가지로, 그 등급을 가진 무기 종류가 로스터에 있어야만 달성 가능하다. 상세 현황은 11장 참고.

**콘텐츠 볼륨은 의도적으로 최소화한다.** 칭호를 의미 있게 만들려면 최소 30개 안팎, 도감도 20개 이상 항목이 필요해 보이지만, 이 프로젝트의 목적 대비 과잉 투자로 판단해 **시스템(조건 트리거·저장·표시 구조)만 다지고 콘텐츠는 최소 세트만** 채운다. 콘텐츠가 실제로 늘어나면 볼륨을 자연스럽게 확장한다.

생존시간/처치수는 기존대로 기록/랭킹 성격으로 활용해 '비교하는 재미'는 주되, 파워 이득으로 직결시키지 않는다.

## 9. 기술/플랫폼 고려사항

### 9.1 개발 순서

**웹(WebGL) 우선 → 모바일 이식으로 변경**

- **사유**: 현재 모바일 실기 테스트 환경이 열악하다.
 - 웹 빌드는 데스크탑에서 바로 반복 확인이 가능해 개발 속도가 빠르다.
- **부수 이점**: Unity 기본 템플릿이 데스크탑(마우스/키보드) 입력을 기본으로 제공하므로, 웹 우선 개발이 오히려 초기 셋업 비용이 더 낮다.
- **설계 유의**: 처음부터 '마우스 커서 방향'과 '가상 조준 스틱 방향'이라는 두 입력원을 하나의 추상화된 **조준 벡터**로 다루도록 설계하면, 이후 모바일 이식 시 조작 로직을 갈아엎지 않아도 된다.
	- Input System 액션맵으로 PC/모바일 바인딩을 분리하는 것을 권장한다.
- 배포처(itch.io, 자체 호스팅 등)는 미정이다(열린 질문, 11장).

## 10. MVP 범위 정의 (개발 착수 기준)

**포함**
- 단일 아레나 엔드리스 서바이벌 (A안)
- 근접/원거리 2종(확장 가능한 데이터 구조로 구현)
- 내구도 소모: 근접=명중 시, 원거리=발사 시
- 무기 슬롯 1개, 필드 스폰 + 자동 교체 + 수동 드랍 버튼
- 맨손 시작
- 적 단일 유형(접촉 데미지)
- XP/레벨업 + 3택 증강 시스템(전역 스탯 적용)
- **PC(마우스+키보드) 조작 우선 구현**, 모바일 트윈스틱은 2차 구현
- 칭호(타이틀)·무기 도감 최소 세트 (화폐 없이 조건/발견 기반, 파워 무관. 7.2 참고)

**제외 (후순위)**
- 무기 등급/희귀도, 이동속도 페널티, 슬롯 확장
- 3번째 이상 무기 대분류
- 적 유형 다양화(6.1 확장안, 무기-적 상성은 폐기)
- 무기 특화 증강
- 조준 자동 보정(스냅/자석)
- 스토리/세계관/최종 아트, 모바일 UI 폴리싱
