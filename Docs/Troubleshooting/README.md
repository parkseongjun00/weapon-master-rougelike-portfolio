## 0. 일러두기

- **목적과 범위**
	- 같은 실패를 반복하지 않도록 문제 하나의 가설·시도·결과·판단을 조사 순서대로 보존한다.
	- 여러 세션에 걸쳐 조사해도 같은 문제는 한 파일에 이어 쓴다. 파일명은 생성 순서에 따라 `NN-Topic.md`로 정한다.
	- 기록은 당시의 환경과 판단이다. 현재 구현 명세로 사용하지 않는다.
- **공통 목차**
	- 각 기록은 `1. 문제 요약`·`2. 조사 경로`·`3. 결과`·`4. 변경 이력`으로 구성한다.
	- 문제 요약은 증상·조건·상태·결론 또는 중단 지점을 표로 정리한다.
	- 조사 단계는 H3로 나누고 **가설·시도·결과·판단**을 같은 순서의 굵은 상위 불릿으로 쓴다.
	- 문서 조사·미실행·미채택·실패·해결을 구분한다. 실행하지 않은 시도나 확인하지 못한 원인을 만들어 넣지 않는다.
- **표현과 보존**
	- `WritingGuide.md`를 기본으로 적용하고 비교는 표, 독립적인 요점은 불릿, 연결된 설명은 짧은 문단으로 쓴다.
	- 조사 경로는 본문에 보존한다. 실패 조건·오류 문구·반박 근거는 남기고 반복 설명만 압축한다.
	- 관찰 결과·추론·제안을 구분하며, 나중의 결론으로 당시의 오판이나 중단을 성공한 과정처럼 고쳐 쓰지 않는다.
- **결과와 참조**
	- 결과에는 채택한 해결책 또는 중단 이유와 재사용할 판단을 적는다. 확정된 주요 기술 결정의 상세는 DevNotes로 연결한다.
	- 미해결 작업을 백로그로 자동 등록하지 않는다. 사용자 요청 또는 등록안에 대한 동의가 있을 때만 이관한다.
	- 임시 문서를 영구 근거로 참조하지 않는다. 후속 결과는 보존 문서로 연결하고 기존 절을 옮기면 참조도 유지한다.
	- 편집 전에 이 파일과 대상 기록을 함께 읽는다.
