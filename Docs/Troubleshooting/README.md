# 트러블슈팅: 공통 규칙과 색인

> 공개 편집본 p1 · 2026-10-23 · 원본 `703affa`. 현재 안내는 [공개본 문서 색인](../README.md)을 따른다. 과거 기록은 당시 상태이며 현재 코드 전체의 검증 결과가 아니다.

이 폴더는 하나의 문제를 조사하며 거친 시도, 실패 원인, 분기와 최종 결과를 보존한다. `DevNotes/`가 확정된 결정과 이유를 압축해 기록하는 곳이라면, 이 폴더는 같은 막다른 길을 다시 밟지 않도록 조사 경로 전체를 남기는 곳이다.

---

## 0. 일러두기

1. **문제 하나당 기록 파일 하나를 사용한다.**
	- 여러 세션이나 도구에 걸친 조사도 같은 문제라면 한 파일에 이어서 기록한다.
	- 새 결정 하나마다 파일을 만들지 않는다.
2. **실패 경로를 보존한다.**
	- 잘못된 가설, 시도한 방법, 실패 원인과 다음 분기를 조사 순서대로 남긴다.
	- 결론이 난 뒤에도 이전 경로를 성공한 과정처럼 고쳐 쓰지 않는다.
3. **`WritingGuide.md`를 기본으로 적용한다.**
	- 표기, 탭 들여쓰기, 제목 번호, 섹션 구분선과 담백한 문체를 따른다.
	- 조사 경로를 보존하기 위해 필요한 상세 서술은 압축 대상에서 제외한다.
	- 기존 기록은 새 규칙에 맞추기 위한 목적으로 내용을 다시 쓰지 않는다.
4. **파일 번호는 기록 생성 순서를 따른다.**
	- 파일명은 `NN-Topic.md` 형식을 사용한다.
	- 번호는 개발 단계 번호가 아니다.
	- 각 파일의 `##` 번호는 해당 조사 문서 안에서 1부터 독립적으로 시작한다.
5. **결과를 성격에 맞는 문서로 이관한다.**
	- 확정된 주요 기술 결정은 `DevNotes/`의 관련 기록 파일에 압축해 남긴다.
	- 해결되지 않은 미래 작업은 `Backlog.md`로 옮긴다.
	- 사용자 결정 전 제안은 `DiscussionDraft.md`나 현재 대화에 둔다.
	- 이관 뒤에도 조사 경로 자체는 이 폴더에 보존한다.
6. **편집 전에 이 파일과 대상 기록 파일을 함께 읽는다.**
	- 각 기록 파일 상단은 이 파일을 공통 작성 규칙으로 가리킨다.
7. **정확한 교차 참조를 유지한다.**
	- 다른 문서가 조사 경위를 참조할 때는 파일명과 관련 절을 함께 적는다.
	- 파일을 옮기거나 개명하면 참조 경로도 함께 갱신한다.
