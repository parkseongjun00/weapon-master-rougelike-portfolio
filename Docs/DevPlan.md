## 1. 구현 순서 원칙

1. 하드코딩 우선, 추상화는 나중. 코어 루프의 재미를 먼저 검증하고, 데이터 기반 구조로의 리팩터링은 그다음에 한다.
2. 세로로 얇게 쌓는다. 기능을 한꺼번에 완성하기보다, 항상 플레이 가능한 상태를 유지하면서 하나씩 붙여나간다.
3. 막히면 범위를 줄인다. 진행 중인 단계 안에서도 상대적으로 덜 중요한 항목부터 먼저 덜어낸다.

## 2. 단계별 계획

> 단계 완료 표시는 당시 확인 기록이다. 현재 공통 전투의 세부 회귀까지 통과했다는 의미는 아니다. 피격 표현은 개발 노트5.16~5.24에서 후속 구현했으며, 6단계의 초기 항목과 구분한다.

### 2.1 1단계: 코어 루프 구현

게임의 핵심을 최소화된 형식으로 구현.

- 플레이어 이동/조작
	- WASD 이동
	- 마우스 방향 조준(캐릭터 회전)
- 레벨/아레나
	- 아레나 바닥
	- 경계 처리(보이지 않는 벽)
- 카메라
	- 쿼터뷰 각도/거리 세팅
	- 플레이어 추적
	- 휠 FOV 줌과 건물 충돌·상체 시야 가림 시 거리 축소·복원
- 무기 시스템
	- 근접 1종 + 원거리 1종 (스탯 하드코딩)
	- 필드 스폰
		- 고정 스폰 포인트
		- 주기적 리스폰
	- 픽업(상호작용 버튼, 슬롯 1개)
	- 무기 교체
		- ① 기존 무기 자동 드랍(플레이어 현재 위치)
		- ② 신규 무기 장착
	- 상호작용 버튼으로 드랍
	- 내구도 소모
		- 근접: 명중 시 소모
		- 원거리: 발사 시 소모
	- 파괴 시 맨손 전환
- 전투
	- 근접 공격 판정: 활성 타격 구간의 Collider 접촉, 대상별 공격당 1회 피해
	- 원거리 투사체: 최초 명중 대상에만 데미지 후 소멸(피어싱 없음)
- 적 시스템
	- 기본 공격 유형을 적용할 적 프리팹
	- NavMesh 경로 추종 이동(우회·밀집·재사용의 개별 확인 범위는 개발 노트5.30~5.34 참고)
	- 유형별 공격으로 플레이어 피해 처리(GDD 6.1, 기본 적 펀치 적용·사용자 타격 확인, 세부 회귀 별도)
	- 적 체력/사망 처리
	- 사망 즉시 사전 정의된 XP 값을 플레이어에게 가산(오브젝트 스폰 없음)
	- 스폰 로직: 첫 번째 제한형 맵의 경계 부근에서 플레이어와 일정 거리 이상 떨어진 위치를 무작위 선택(단순 타이머)
- 플레이어 생존
	- 플레이어 HP
	- 피격 처리
	- 사망 → 재시작
- UI
	- 체력바

### 2.7 6단계: 세계관/타이틀/비주얼

코어 루프와 콘텐츠가 검증된 뒤, 보류해두었던 나머지 세계관 세부·비주얼을 진행하는 단계.

- 세계관 사건·조직 설정 구체화
- 비주얼 아트 스타일 확정
- 리소스(무기/적 모델, 텍스처, 사운드, UI 스킨 등) 제작 및 적용 — 플레이어 캐릭터 모델/애니메이션은 4단계에서 선행 적용됨
- 게임 타이틀 확정
- 피격 시 반짝임 효과(적/플레이어 공통) *(2026-07-28 추가. 비주얼 항목이지만 아트 스타일 확정과 무관한 저비용 연출(머티리얼 컬러 플래시)이라, 최종 리소스 적용을 기다리지 않고 이 단계 초반 placeholder 컬러로 먼저 구현 가능)*

세계관 '기획'(구상·문서화) 자체는 코드 작업이 아니므로, 2단계가 끝나 코어 루프가 실제로 재미있다고 확인된 시점부터 이 단계와 무관하게 미리 병행해도 된다.

- 현장에서 싸울 수단을 확보·교체하는 콘셉트를 문서에 반영했다. 적 정체성과 비주얼 분위기는 디자인 세션에서 검토한다.
- 적 디자인 검토는 [적 디자인 기준](Art/EnemyDesign.md)에 따라 병행한다.
- 공격 유형 검토는 기존 대표 모델을 재사용할 수 있으며, 새 모델 제작을 선행 조건으로 두지 않는다.
- 신규 외형이 필요하면 적 콘셉트·디자인 검토 → 해당 리소스 제작 요청 → 인게임 시점 확인 → 후속 확대 순서로 진행한다.
- 대표 적의 복장·실루엣·피격 표현을 먼저 확인하고, 원거리 적 등 신규 공격 동작은 규칙과 제작 범위를 확정한 뒤 진행한다.
- 현재 전투 상태: 공통 무기·모션과 기본 적 펀치 적용. 다음 범위는 무기 추가·역할 구분이며 적 유형 확장은 보류한다.
- 공통 무기·모션과 기본 적 펀치를 적용했다. 플레이어 회귀 → 단독/다수 적의 회피·반격 확인 → 예고 보강·다음 유형 판단 순서로 진행한다.
- 전체 개발 단계 순서와 첫 맵 제작 범위는 유지한다. PVP와 추가 스테이지의 구체적인 제작 계획은 보류 과제로 다룬다.

- 첫 맵 환경 작업의 기준은 [Art/FirstMap.md](Art/FirstMap.md)와 해당 배치도다. NW03 한 채의 외관·독립 재질 시제품을 선행 제작했다. 후속 현실성 개선과 확대 제작의 개별 착수 범위는 후속 요청에서 확정하며, 상세 구현은 [환경 아트 개발 노트](DevNotes/04-EnvironmentArt.md), 열린 과제는 [Backlog 16](Backlog.md#16-nw03-현실성-개선과-환경-리소스-검증)을 참고한다. 전체 개발 단계 순서는 유지한다.
