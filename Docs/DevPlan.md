# 웨폰마스터 로그라이크(가제) 개발 계획 v0.20
- 개발 인원: 1인(전업)
- 기반 문서: `Docs/GDD.md` v0.29, `Docs/Systems.md` v0.14

이 문서는 '언제 무엇을 만들지'만 다룬다. 특정 스테이지 작업 중 확정되는 '어떻게 만들지'(컴포넌트 구조, 저장 방식 등 기술적 의사결정)는 `Docs/DevNotes.md`에 스테이지별·시간순으로 별도 기록한다. 아래 각 단계 항목에 그런 세부 결정을 다시 누적하지 않는다.

---

## 1. 구현 순서 원칙

1. 하드코딩 우선, 추상화는 나중. 코어 루프의 재미를 먼저 검증하고, 데이터 기반 구조로의 리팩터링은 그다음에 한다.
2. 세로로 얇게 쌓는다. 기능을 한꺼번에 완성하기보다, 항상 플레이 가능한 상태를 유지하면서 하나씩 붙여나간다.
3. 막히면 범위를 줄인다. 진행 중인 단계 안에서도 상대적으로 덜 중요한 항목부터 먼저 덜어낸다.

---

## 2. 단계별 계획

### 2.1 1단계: 코어 루프 구현

게임의 핵심을 최소화된 형식으로 구현.

- 플레이어 이동/조작
	- WASD 이동
	- 마우스 방향 조준(캐릭터 회전)
- 레벨/아레나
	- 아레나 바닥
	- 경계 처리(보이지 않는 벽)
- 카메라
	- 쿼터뷰 각도/거리 세팅
	- 플레이어 추적
- 무기 시스템
	- 근접 1종 + 원거리 1종 (스탯 하드코딩)
	- 필드 스폰
 - 고정 스폰 포인트
 - 주기적 리스폰
	- 픽업(자동, 슬롯 1개)
	- 무기 교체
 - ① 기존 무기 자동 드랍(플레이어 현재 위치)
 - ② 신규 무기 장착
	- 수동 드랍 버튼
	- 내구도 소모
 - 근접: 명중 시 소모
 - 원거리: 발사 시 소모
	- 파괴 시 맨손 전환
- 전투
	- 근접 공격 판정: 범위 내 모든 적 동시 타격(다중 히트)
	- 원거리 투사체: 최초 명중 대상에만 데미지 후 소멸(피어싱 없음)
- 적 시스템
	- 적 프리팹(단일 유형)
	- 추적 이동(직선)
	- 접촉 시 플레이어 데미지: 접촉 유지 중 쿨다운마다 반복
	- 적 체력/사망 처리
	- 사망 즉시 사전 정의된 XP 값을 플레이어에게 가산(오브젝트 스폰 없음)
	- 스폰 로직: 아레나 경계 부근, 플레이어와 일정 거리 이상 떨어진 위치에서 무작위(단순 타이머)
- 플레이어 생존
	- 플레이어 HP
	- 피격 처리
	- 사망 → 재시작
- UI
	- 체력바

### 2.2 저장 설계 원칙

WebGL 타겟 특성상 `PlayerPrefs`/IndexedDB 저장 신뢰성 문제가 알려져 있어, 세이브 코드는 `PlayerPrefs`를 직접 호출하지 않고 단일 SaveSystem 창구로만 접근하도록 설계했다. 저장 유실이 확인되더라도 그 창구 하나만 고치면 되게 하기 위함이다(세부는 `DevNotes.md` §3단계 참고).

### 2.3 2단계: 코어 루프를 지원하는 재미 구현

레벨업 및 증강 시스템, 적 난이도 곡선 등 코어 루프의 긴장감과 성장감을 강화하는 요소.

- XP/레벨업/증강
	- XP 누적 및 레벨업 트리거 (곡선 구체값은 튜닝 대상, GDD 11-1 참고. 초기엔 placeholder 값으로 구현 후 플레이테스트하며 조정)
	- 레벨업 시 풀피 회복
	- 증강 후보 풀 + 3택 선택 UI (선택 팝업 표시 중 일시정지)
	- 증강 효과 적용(전역 스탯). 컴포넌트 구조·세부 결정은 `DevNotes.md` §2단계 참고
- 적 시스템
	- Boids 알고리즘(separation) 적용
	- 시간에 따른 스폰 강도 증가(난이도 곡선, 구체 함수는 튜닝 대상, GDD 11-5 참고. 초기엔 placeholder 함수로 구현)
- 런 상태 관리
	- 생존시간/처치수 카운트 및 기록
	- 사망 시 마지막 런 결과(생존시간/처치수)를 로컬에 저장(결과를 보여주는 화면 UI 자체는 4단계 '재시작/메뉴 화면' 소관). 저장 방식은 `DevNotes.md` §2단계 참고
- UI
	- 생존시간/처치수 실시간 HUD 표시
	- 적 체력바 표시 (추가: 3단계 무기 등급/희귀도로 데미지 편차가 생기기 전에, 데미지 피드백을 눈으로 확인할 수단 확보)
	- XP/레벨 게이지 실시간 HUD 표시 (추가: 증강 시스템 플레이테스트에 필요한 HUD가 기존 스코프에서 누락돼 있었음)
	- 피격 시 데미지 수치 팝업 표시 (추가: 적 체력바 도입과 함께 데미지 피드백을 수치로도 확인할 수단 확보. 구현 방식은 `DevNotes.md` §2단계 참고)
- 무기 시스템
	- 데이터(ScriptableObject) 구조로 리팩터링 (후순위 스탯 필드 동시 정의, `Stage1SceneBuilder.cs` 포함). 세부 범위는 `DevNotes.md` §2단계 참고

### 2.4 3단계: 메타 시스템 구현 (재설계, )

런과 런 사이를 이어주는 진행 요소. **파워 무관 원칙 재확인**: 메타 진행은 런 내 전투력에 절대 관여하지 않는다. 착수 전 논의에서 원래 계획(신규 무기 종류/등급 해금, 코스메틱, 메타 재화)을 전면 폐기하고 아래로 재구성했다. 배경은 `GDD.md` 7.2/5.5, 결정 근거·placeholder 수치는 `DevNotes.md` §3단계 참고.

- 무기 시스템
	- 등급(Rarity) 시스템
 - 4단계: 일반/희귀/영웅/전설
 - **무기 종류(정의)에 고정된 값**이며 필드 조우 확률과는 무관(정정, `GDD.md` 5.5 참고)
 - 최종 스탯은 런타임 공식이 아니라 authored 값
	- 컨디션(Condition) 시스템 신설
 - 스폰 인스턴스마다 랜덤으로 소폭 갈리는 공격력 편차
 - 필드 조우가 실제로 확률적인 부분은 등급이 아니라 이쪽(`GDD.md` 5.6 참고)
- 메타 진행
	- 칭호(타이틀) 시스템
 - 조건 달성 시 화폐 없이 즉시 해금
 - 3단계는 시스템만: 콘텐츠는 최소 세트(약 8개)만
 - **화면(뷰)은 만들지 않음**: 로직·저장까지만, 표시는 4단계 메인 메뉴에서
	- 무기 도감
 - 무기 종류 × 등급 조합 발견 기록
 - **재검토 필요**: 등급이 무기 종류에 고정된 값으로 정정되며 '무기 2종 × 4등급 = 8칸' 전제가 깨짐(현재 로스터로는 최대 2칸만 도달 가능)
 - 3.3/3.4 착수 시 슬롯 구성 재설계 필요
 - **화면 없이 로직·저장까지만**
- 런 상태 관리
	- 칭호/도감 해금 데이터 저장(기존 생존시간/처치수 저장과 동일한 SaveSystem 창구로 통합)

**폐기된 항목** (사유는 `DevNotes.md` §3단계 참고)

- 메타 재화(화폐) 시스템 전체
- 신규 무기 종류 해금
- 신규 무기 등급 해금
- 코스메틱 해금
- 무기 서브타입(경량형/중량형/속사형/강격형) 분류 체계 전체: GDD 정리 과정에서 사용자가 설계한 적 없는 개념으로 확인되어 완전 폐기(무기별 정체성은 개별 스탯 authoring으로 부여)

### 2.5 4단계: 기본 리소스 적용 (재배치, )

원래 5단계(비주얼/세계관 적용)에 있던 항목 중 플레이어 캐릭터 리소스만 앞당겨 이번 단계로 가져온다. 게임이 미완성처럼 보이는 것을 막기 위한 목적이며, 나머지 비주얼/세계관 항목(세계관 문서화, 아트 스타일, 타이틀, 모바일, 피격 이펙트)은 6단계로 유지한다.

- 플레이어 캐릭터 모델 적용 (AI 생성, 치비 스타일)
- 플레이어 캐릭터 애니메이션 적용 (이동/조준/공격)

---

### 2.6 5단계: 콘텐츠 확장

플레이 콘텐츠의 폭을 넓히는 단계.

- 무기 시스템
	- 이동속도 페널티
	- 무기 특화 증강
- 적 시스템
	- 적 유형 다양화
- UI
	- 재시작/메뉴 화면
- 기타
	- 밸런스 시트(별도 xlsx 등)로 수치 관리 전환

---

### 2.7 6단계: 세계관/타이틀/플랫폼 이식

코어 루프와 콘텐츠가 검증된 뒤, 보류해두었던 나머지 세계관·비주얼·플랫폼 이식을 진행하는 단계.

- 세계관 확정
- 비주얼 아트 스타일 확정
- 리소스(무기/적 모델, 텍스처, 사운드, UI 스킨 등) 제작 및 적용 — 플레이어 캐릭터 모델/애니메이션은 4단계에서 선행 적용됨
- 게임 타이틀 확정
- 모바일 트윈스틱 조작 구현 *(플랫폼/빌드 항목이지만, GDD 9.1의 '웹 우선 → 모바일 이식' 순서상 최종 이식 작업이 마무리 단계와 맞물려 이 단계에 배치. 위치가 어색하면 조정 가능)*
- 피격 시 반짝임 효과(적/플레이어 공통) *(추가. 비주얼 항목이지만 아트 스타일 확정과 무관한 저비용 연출(머티리얼 컬러 플래시)이라, 최종 리소스 적용을 기다리지 않고 이 단계 초반 placeholder 컬러로 먼저 구현 가능)*

세계관 '기획'(구상·문서화) 자체는 코드 작업이 아니므로, 2단계가 끝나 코어 루프가 실제로 재미있다고 확인된 시점부터 이 단계와 무관하게 미리 병행해도 된다.
